# Per-anchor variable-width strokes

UI-16-013, UI-16-014 and UI-18-029 have a working **partial** implementation. This is not complete Figma width-tool parity.

Select a contour path, choose **Edit vector points**, then open **Per-anchor stroke widths**. Set one saved solid stroke to centered alignment, butt/round/square caps and bevel/round joins, and enable point widths. Choose an anchor and enter its full symmetric width, or enable **Width control handles** and drag either normal handle. Multiple anchors retain independent ratios. Control reduces pointer travel to 10%; widths clamp to the displayed numeric limits. The canvas shows the actual filled band while dragging and commits once on release. The numeric path is keyboard accessible. Escape, Space/navigation, pointer cancellation, window blur, camera/mode/source/selection changes cancel pending work.

Each anchor stores optional `widthScale` relative to the base stroke weight. The stroke opts in with optional `variableWidth: "points"`. Global weight changes scale the profile; zero tip widths and a zero base weight are retained. A zero base weight hides the band and disables handle edits until the base weight becomes positive. A zero-distance click does not rewrite geometry/styles or create Undo history. Disable point widths to return to a uniform stroke; ratios remain saved until a later geometry conversion replaces those anchors.

## Supported geometry and paint

- One saved centered solid stroke, butt/round/square caps, bevel/round joins, no dashes or independent edge widths; existing fill remains a separate paint.
- One to sixteen open straight contours, two or more distinct anchors each, at most 512 total anchors. No nonzero Bézier handles, closed contours or exact reversing corners.
- Positive node/path coordinate boxes, at most 1,000,000 units per dimension; centerlines within ±995,000 local units. Purely horizontal/vertical paths whose editing conversion collapses a coordinate dimension need a nonzero coordinate box before enabling this profile.
- Per-anchor ratio 0–64, maximum full local width 10,000. Interactions require a visible, unlocked, detached hierarchy with at most 64 ancestors and finite invertible transforms; UI scale and signed affine ancestry are included in hit testing.
- No arrowheads, legacy blur/shadow, visible effects, or direct width/height animation tracks while a profile is active. Transform-scale animation remains available. Profile controls require Motion closed and mask inspection off. Entering mask inspection cancels pending handles and numeric drafts; retained callbacks cannot revive after an inspection cycle.

Every edge is an exact tapered quadrilateral. Bevel joins add exact triangles. Round joins add the exterior minor circular sector; round caps add exterior semicircles and square caps extend the endpoint by half its width. All pieces have consistent winding and render as **one nonzero filled path**, so overlapping pieces do not accumulate translucent alpha. Normal handles use the unit bisector at interior corners; widths remain perpendicular to each adjoining edge, and this handle convention does not assert arbitrary Figma corner/tool parity. Bézier envelopes, asymmetric widths, miter width joins, pressure input, brush profiles and editable Figma width-tool interchange remain unimplemented.

## Curves, tapers and width points

Point widths need straight open contours, and that rule is enforced by every existing build, so a profile on real Bézier segments would make files unreadable to them. **Convert curves and enable** instead turns an open curved path into straight anchors that follow it, within a tolerance starting at 0.1 layer units and coarsening up to 4 units to stay within 512 anchors. A curve that still will not fit is refused. Original anchors stay, and width scales interpolate across new ones. Round joins keep the band visually smooth, and a miter join or a non-centered stroke is switched to round and centered as part of the conversion. The curve handles are replaced, so reshaping afterward means editing anchors, and Undo restores the original curve. Closed paths are refused, and dashed strokes are refused with the existing message.

**Taper** sets every anchor from a preset: uniform, start, end or both ends. Presets are linear along each contour's real length, so dense and sparse anchors taper alike. A preset replaces existing ratios in one Undo step. **Add width point** inserts a straight anchor between two anchors at a chosen percentage, with an interpolated width, so the centerline does not move. It uses the segment after the selected anchor, or the one before a last anchor, and selects the new anchor.

No curved-envelope geometry, closed-contour profile or asymmetric width exists, and width points can only be placed numerically, not by clicking the stroke.

## Persistence, layout and interchange

Optional metadata is accepted by existing `.oui` versions 1 and 2 without migration. Import, clipboard and headless MCP transactions validate before mutation; malformed fields, incompatible style/topology changes and invalid batches reject atomically. Local component source changes propagate width metadata to managed copies. Managed copies and inherited locks remain read-only. Geometry-local profiles cannot be captured in or overwritten by a reusable stroke style; disabling the profile permits ordinary style workflows again. Scalar base-weight/color bindings continue through the existing design-system pipeline if the resulting profile is valid.

Ordinary point moves and supported surviving-anchor deletion preserve ratios. Geometry normalization, smoothing, curve conversion, Boolean operations, group flattening, cutting, erasing, outlining, offsetting and region separation refuse active profiles before dropping width metadata. Entering/leaving point editing does not bake an active profile. Width/height auto-layout changes retain the original path basis; maximum profile radius participates in stroke-aware sibling spacing and hug measurement. Layout uses a conservative maximum radius, expanded by √2 for square caps, rather than a paint-tight tapered envelope.

Canvas, SVG, PNG/JPEG/PDF raster consumers and alpha/vector/luminance mask source rendering use the same band geometry. Artwork and mask regions conservatively include off-box profile anchors plus their maximum radius. Padding can exceed the exact painted shape. Frame clipping, explicit layer/frame/slice viewports and export crops intentionally retain their normal crop semantics. Outline view continues to show the centerline. Approximate Dev CSS warns and omits the profile.

Editable Figma Bridge import refuses active profiles **before creating Figma nodes**, with SVG/PNG guidance. Inactive saved ratios are validated and explicitly reported as omitted while transferring the uniform stroke. No binary `.fig` compatibility or real Figma desktop round trip is claimed by API-mock tests.
