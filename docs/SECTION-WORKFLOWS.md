# Local sections and layer status filters

Sections have a dedicated Design inspector with a title, a local Ready for development checkbox, direct-child selection, a parent-section selector, and a local link. Mutations use document transactions, support Undo/Redo, and survive .oui save/reopen. `readyForDevelopment` is optional on section nodes in version 2 documents; version 1 imports retain the optional field. Both file parsing and editor transactions reject invalid values or readiness on other layer kinds.

Titles accept 1–512 characters without control characters. Inherited locks and managed instance sections block metadata and structure edits. Nesting uses the existing world-transform-preserving hierarchy planner and rejects cycles and invalid destinations. Sections can move into and out of auto layout parents. A section holding animated layers can move too, as long as no ancestor on either side is animated or transformed, because its keyframes keep their meaning; it stays out of auto layout, and any other case refuses with the reason. Whiteboard/Slides structure changes remain in their workspace controls. Contents selection chooses visible, unlocked direct children, rather than flattening nested content.

A `forma-section:` token contains only the current document/page/section identifiers. Copy local section link displays the token even if clipboard permission fails. Open local section link, below Layers, validates the currently open file and destination, clears filters, selects the section/page, and finds it on the canvas. It creates no public URL, hosting, sharing permission or external protocol handler. Missing/deleted sections and links for a different open file are refused without editing the document.

The layer status selector combines with type and name filters and preserves ancestor paths. It supports saved export settings or slices, explicitly ready sections, configured prototype reactions/legacy destinations/flow starting layers, layers carrying a durable anchored comment, and geometric intersections with local comment pins. The comment filter includes resolved pins and accounts for rotated/scaled geometry; an anchored comment matches its layer by identity wherever its pin lands, and a missing anchor falls back to the saved position. Pins remain canvas coordinates, so this is not a durable layer comment attachment. Hidden/locked layers remain inspectable in layer filters, as in the existing layer tree. Status filters are workspace UI state and do not dirty the project.

Ordinary groups expose an explicit Fit group bounds to children action. It reuses guarded frame fitting, preserving child world geometry and restoring source constraint metadata before final validation. It includes hidden direct children, excludes stroke/effect padding, rejects empty, locked, managed, boolean and auto-layout groups, and refuses cases where layout would move the artwork. Existing group blend mode controls support the renderer's 16 blend modes and isolation, but a separate Figma pass-through blend mode is not added by this work.

Validation: `tests/section-workflows.test.ts` (13 core tests), `tests/e2e/section-workflows.spec.ts` (6 browser interaction tests), TypeScript compilation, and the complete 720-test core suite passed in the isolated source checkout. The browser tests cover save/reopen, Undo, nested transforms, cycle refusal, direct contents, local cross-page links, filters, inherited locks, malformed imports, group fitting and the existing rendered multiply blend mode. The pin classifier also checks 20,000 layers against 10,000 pins. These checks do not establish reference verification against Figma desktop.

## Automatic group bounds

A plain group refits to the rectangles of its direct children on every edit that moves, resizes, rotates, adds or removes one, including nested groups from the inside out. Children keep their geometry, so artwork does not change, and the refit is part of the same Undo. Generated instance groups follow their main without recording an override.

Layers keep their saved bounds when nothing inside them changed, so opening an older file changes nothing. Automatic fitting skips rotated, flipped or scaled groups, Boolean and mask groups, clipped or painted groups, auto layout or guide-bound groups, fill-sized groups and groups with Motion tracks; the explicit Fit group bounds action still covers rotated and scaled groups. Bounds use layer rectangles, without stroke or effect padding. Headless MCP edits outside the editor store do not refit. Validation: tests/group-auto-bounds.test.ts and tests/e2e/group-auto-bounds.spec.ts.

## Section and frame fit

**Fit section to contents** moves and resizes a section around its direct children in one Undo step, and the layers inside stay where they are. It uses the frame fit rules, so empty, locked, managed and motion-controlled sections refuse.

**Keep fitted to contents** (section and frame inspectors) saves an optional `autoFit: {padding}` on the layer. From then on the box follows its direct children on every editor change, in the same Undo step as that change, with a padding of 0 to 10,000. It is off by default, and nothing changes in a file that does not turn it on. It uses layer rectangles and skips rotated, flipped, scaled, fill-sized, auto layout and animated layers; the checkbox refuses them with a reason. A saved frame or section with invalid `autoFit` refuses before the file opens. Older Forma builds ignore the field and keep the saved bounds. Validation: tests/container-fit.test.ts and tests/e2e/container-fit.spec.ts.
