# Explicit in-app learning and canvas tour

**Help → Learning & canvas tour** opens local onboarding guidance. The canvas **Tool help ?** button opens help for the actual current tool. Neither starts automatically, creates tutorial artwork or changes startup behavior. These are Forma guidance, not a claim of exact Figma onboarding/reference parity.

The Learning dialog has keyboard-accessible Getting started, Tool help and Guide links tabs. Tool explanations cover the actual seventeen toolbar choices; the help selector only changes which explanation is read. Shortcut labels come from the current supported command catalog and keyboard preferences, including additional local bindings. The dialog links to the existing keyboard-shortcut view rather than inventing a second shortcut list. Specialized inspector tools retain their own nearby scope/refusal descriptions.

The explicit **Start canvas tour** button requires a visible Design or Whiteboard document in Design mode, with Motion and dialogs closed. It closes its own Learning dialog through a guarded handoff, then points to six actual current controls: canvas, design toolbar, pages/layers sidebar, inspector tabs, zoom and Actions. Previous/Next/Finish/Stop and Escape are real navigation controls. **Focus highlighted control** focuses a visible eligible existing element with `preventScroll`; it never clicks that control or changes the selected tool, artwork, camera, page or selection. The tour does not force collapsed sidebars open. Missing/hidden targets show instructions and allow continuing. Slides and other unsupported contexts refuse rather than pretending to show a Design tour.

The highlight uses measured physical CSS-pixel rectangles, viewport/overflow intersections and up to 64 ancestors. Inert, aria-hidden, display/visibility/zero-opacity ancestors suppress it. Focus additionally refuses native disabled controls, disabled fieldsets and aria-disabled ancestry, even with an explicit tabindex. The bounded focus search visits at most 200 descendants. Resize, scroll and bounded ancestor-attribute/child-list observations update geometry and availability. Replacing a live target unobserves its previous ResizeObserver element; only the document root, card and current target remain observed. Cards use measured height, remain within the viewport and scroll internally when needed. Their explicit opaque light/dark surfaces do not depend on `.app` variables leaking into the body portal.

Tour/source receipts capture the exact document, page, selection, mode/modal/home/interface/Motion state, tool, Assets/Layers choice and UI scale. Any observed departure permanently retires the old tour, including away/back cycles; fresh controls can start another. Immutable local step/choice receipts prevent retained callbacks from navigating a newer step or restarted tour. Pending focus is one-use and checks source/local ownership, live eligibility and window focus again before delivery; blur cancels it permanently. Dialog and tour opener return only occurs into the still-current source and connected eligible element. Nothing is added to `.oui`, Undo, recovery, clipboard, exports, library packages, plugins or source MCP schemas.

Guide links are fixed HTTPS URLs for the existing Forma preview guide, product page and privacy page. Local website files were confirmed and all three live URLs returned HTTP 200 HTML through read-only requests during this pass. No request is made until an explicit link activation; links use a separate browsing context with `noopener noreferrer` and include no project identifiers. The preview guide can lag newer source features, so visible in-app limits and the feature register remain important. No cloud help service, tutorial file, support account or network API is invented.

This implements an opt-in local onboarding/contextual-help/help-link path for UI-47-025/027/028. **UI-47-026 first-run behavior remains incomplete:** the manual canvas tour does not detect first installation, distinguish upgrades/cleared browser storage, display an automatic first-run hint or start a tour on launch. No startup markers or new profile preference are saved. Native WKWebView focus/link behavior and original-reference verification remain pending under the build freeze.

Source checks cover real content/command identities, bounded rectangle placement and permanent source/modal-handoff proofs. Actual Chromium checks cover all six measured targets, read-only state/history, current shortcut labels, native keys and tab navigation at 125%/short viewport, collapsed targets, hidden/inert/disabled eligibility and recovery, local/source/modal/tour restart focus races, fixed-link navigation with zero automatic requests and an unfinished Pen draft that is never committed by help activation. No app/native build or archive was produced.
