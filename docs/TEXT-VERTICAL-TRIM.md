# Text vertical trim

The text inspector’s Paragraphs/All settings include **Text vertical trim → Cap height to baseline**. This is an outer text-box setting, not a per-paragraph or character style. The optional `textVerticalTrim` enum is `none` (also the behavior when absent) or `cap-height`; `.oui` versions 1/2 remain compatible without a required migration.

For supported first-line typography, shared layout measures an uppercase **H** with each distinct first-line font face/size/weight/style using browser Canvas `TextMetrics.actualBoundingBoxAscent`. The largest reference supplies the first cap edge, including a separate list marker’s face where applicable. Every baseline shifts by the same leading adjustment, preserving relative baseline intervals, wrapping, paragraph spacing, source characters and logical UTF-16 offsets. The body ends at the baseline envelope rather than including positioned descender overflow. With ordinary increasing baselines this is the last baseline; deliberately overlapping fixed-leading lines use the highest baseline to keep a finite nonnegative body.

Supported trimmed auto-height/auto-width measure natural top-aligned geometry, so an old fixed box height cannot feed back through middle/bottom alignment. Fixed-box top/middle/bottom alignment uses the trimmed body; ellipsis height fitting uses that same body and preserves the original formatted first-line font reference. Existing font-refresh handling remeasures actual fonts without adding a user Undo entry. The cap reference is not cached, so a newly loaded or replaced font immediately changes the measured geometry.

## Supported limits and visible fallback

This is **partial** vertical trim, not exact Figma font-edge parity. The reference is the actual browser-rendered Latin H, not a font’s OS/2 cap-height table or a language-specific ideographic edge. Missing H glyphs or unavailable faces may use browser fallback. No font-coverage or availability claim is inferred from a numeric measurement. The inspector reports the cap reference and leading adjustment, and explicitly reports ordinary-layout fallback where it cannot provide a compatible reference.

Up to 64 distinct plain first-line font styles are supported. Explicit first-line variable axes, features that can change capitals, small capitals and raised/lowered positions retain ordinary geometry because Canvas H metrics do not match those SVG shaping paths. Features set to 0, and `liga`, `clig`, `dlig`, `calt`, `kern`, `tnum`, `pnum`, `lnum`, `onum`, `frac` and `zero` at any value, keep trim, because they cannot change the height of a capital H. Stylistic sets and other features stay on the fallback, since their effect on H is font-specific. Empty run axis/feature maps retain the layer’s actual inherited settings when checking this limit. Later rich positions can still extend outside the body. A browser without a finite usable H metric also retains ordinary geometry. Unsupported cases preserve the existing untrimmed auto-size/alignment behavior as well; no unrelated legacy alignment repair is applied. In headless layout the reference is explicitly an approximate 0.7 em; headless sizes can differ from browser typography. No glyph metrics are persisted as if they were font-independent facts.

Accents, descenders and rich positions may paint outside the trimmed body. Shared SVG canvas/export/mask rendering retains those glyphs, and conservative transformed visual bounds/mask regions include room for their ink. Bounds are not paint-tight and do not promise arbitrary font-binary bearing extremes. Explicit frame clipping, slice crops or fixed export viewports can deliberately crop that overflow. A text background follows the trimmed box geometry. Imported glyph outlines invalidate when the appearance setting changes, then shared editable layout takes over.

## Persistence and interchange

Changes use ordinary Undo/save, whole-layer copy/paste, component inheritance/overrides and local text styles. Rich character/paragraph fragments intentionally do not carry this outer-box property into another text layer; destination trim remains its own setting. The optional enum is validated on documents, styles, MCP operations and the Figma Bridge before mutation. Malformed values, including `null`, booleans and unknown strings, are rejected atomically. Inspector context proofs reject locked ancestors, Motion, changed selection/page/document, hidden UI, mode changes, font-revision changes and same-event context changes away and back.

CSS inspection states that its one-rule output omits the measured SVG baseline behavior. Editable Figma transfer validates the metadata and reports that vertical cap-height trim is omitted; shared SVG preserves the appearance. This is not evidence of an actual Figma desktop plugin round trip.

## Verification

Core cases cover default compatibility, explicit headless estimates, mixed fonts and markers, interval/source preservation, unsupported shaping and budgets, natural auto-size under all vertical alignments, descender overflow, finite overlapping-leading/ellipsis behavior, rich clipboard boundaries, validation/Undo, real generated component copies, text styles and Bridge atomic refusal/omissions. Browser cases compare actual H top pixels and Canvas cap references, export accents/descenders through all three mask modes and transforms, test intended frame clipping, save/reopen/Undo, exercise mixed-face baselines and late actual font loading, and reject stale/locked/Motion/font-revision handlers. Source MCP checks cover atomic validation, persistence and Undo without running package-producing test hooks.
