# Mac document windows

Forma's AppKit shell owns a separate `DocumentWindow` controller, WKWebView, file association and document state for each open window. New design, whiteboard, slides and sample commands create a new window. File → Open accepts multiple `.oui`/JSON projects; opening an already open path or document identity focuses that document. Home's saved-document Open also creates or focuses its own window. Each renderer validates a loaded document before replacing its initial placeholder.

Native menu commands target the key document window. Window → Close closes that window; closing the last window leaves the application running. The Dock offers new workspace windows and recent saved files. File → Open Recent uses macOS recent-document records. Reopen Closed Window (`Shift–Command–T`) restores the last closed window's local recovery copy when it remains available.

Window titles and macOS's edited indicator follow the renderer's actual document content. Returning to saved content through Undo clears the edited state even if the document timestamp differs. A successful save acknowledges the exact captured document; edits made while saving remain dirty. A cancelled or failed save does not clear dirty state or approve closing.

Closing a dirty window offers Save, Cancel and Don't Save. Save closes only after native file writing and renderer acknowledgment complete and the window remains clean. Closing also flushes focused inspector edits and attempts a local recovery write. If the renderer cannot confirm its state, a separate warning requires an explicit Close Without Saving decision. Quit checks document windows in sequence; cancellation keeps the remaining windows open. Windows already approved before a later cancellation can have closed.

Window sessions retain document IDs, native file URLs and window frames in the application's preferences. Project contents remain in the validated local project repository. Multiple windows share that library and font/preferences storage, but each bootstraps its own document ID instead of reading a shared global active-file pointer. Clean saved sessions reopen from disk, including changes made by external tools while Forma was closed. Dirty sessions use their own local recovery. Normal Quit retains approved saved sessions for reopening; an explicit Don't Save restores the saved file's contents on relaunch, and an unsaved discarded draft does not reopen automatically. If a saved file cannot be read, an explicit choice offers its local recovery or skips reopening; that recovery can include previously discarded edits. Opening a Finder file at launch also preserves previous window sessions. Automatic restoration preserves library trash/deletion metadata; only a validated explicit external file open can revive that identity. Closing individual windows removes them from automatic session restoration. Old single-window installations use their previous active local recovery once on migration.

Safeguards and limits:

- Native project input and saves are limited to 50 MB. Reads use bounded, nonblocking regular-file descriptors and reject FIFOs and symlinks at that boundary. Export formats retain their separate bounded bridge limits.
- Normal Save compares the saved/opened SHA-256 disk revision. An externally changed or removed file requires Cancel, Save As or explicit Overwrite; the approved revision is checked again before writing. Native and MCP writes use the same exclusive transaction lock. A crashed writer can leave a lock requiring manual cleanup. This coordinates cooperating writers; it does not add live synchronization or eliminate races with unrelated programs that ignore that lock.
- Pre-ready native document commands and saves are rejected. A save must match its window's document identity.
- A file already associated with another live window cannot be overwritten through a second window's Save As.
- No arbitrary filesystem path is exposed to the renderer. Only bundled editor resources are served at `127.0.0.1:51981`; each IPC request must originate from that window's main-frame app origin.
- Local recovery normally follows editor changes after a short debounce. An abrupt process or machine failure can lose the latest changes; a local recovery copy does not replace a saved `.oui` backup.
- A valid saved file still opens for editing if its local-library write fails. The editor warns that it is open in memory and needs a `.oui` backup. Native file association, dirty state and acknowledged saving remain intact; local recovery and library revival are unavailable until storage succeeds. Invalid file input never uses this fallback.
- Reopen and session restoration depend on available local recovery or saved files. Removed files, cleared storage and deleted library records cannot be recreated by the window manager.
- Opening multiple independent copies with the same document ID focuses the already open document; it does not merge divergent copies.
- Native design-node Copy/Cut/Paste uses bounded editable Forma, SVG and plain-text pasteboard representations across document windows. Transfers validate complete references before one undoable edit; linked components copied to another document get independent local definitions. Cutting a main still used by surviving layers is refused before writing. External SVG uses import review. Explicit PNG/TIFF paste normalizes the first oriented frame with size guards; the development source adds 2× Copy as PNG, pending final native window acceptance. Browser/Windows system images and private Figma clipboard formats remain unfinished. The browser preview retains its local design clipboard. See [clipboard behavior and limits](NATIVE-CLIPBOARD.md), [raster paste](RASTER-CLIPBOARD.md) and [PNG copy](COPY-AS-PNG.md).
- The renderer and shell are still an evolving design editor. Multiple windows do not imply shared real-time editing, native document tabs, cloud synchronization or complete Figma parity.
