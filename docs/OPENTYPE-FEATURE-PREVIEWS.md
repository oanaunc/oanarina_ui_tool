# OpenType feature comparisons

The text inspector’s OpenType tab (or the comparison disclosure in All) provides a real browser-rendered current/candidate specimen and a guarded **Apply feature to selected characters** action. Both sides use the same source fragment, fonts, character sizes, weights, axes, tracking, small capitals, baseline positioning and unrelated feature settings. Only the chosen OpenType feature changes. Source mode preserves the original paragraph’s resolved direction and physical alignment, even when a neutral substring is selected. A local editable example uses its own paragraph direction and never replaces document text.

Previewing is local UI state. Applying changes only the selected safe UTF-16 character range, preserves other run properties and effective feature settings, creates an ordinary undoable document edit, and persists through the existing `.oui` rich-text fields. Empty run feature/axis maps inherit layer settings just as they do in Artwork; applying a feature materializes those effective feature settings only in the selected range. Mixed nonempty run maps retain their existing replacement semantics. No new document schema, font distribution, native IPC or MCP fields are introduced.

A custom tag must contain exactly four alphanumeric characters. Leave its field to update the displayed comparison before applying; uncommitted or invalid tag/value drafts disable Apply. Live field, selection/source, document, page, mode, visibility, font revision, Motion and lock checks refuse stale actions. A retained action is invalidated even if the context changes away and back in one event. Already-set eligibility checks the entire selected source range, independently of the clipped/example specimen. A collapsed caret can preview but cannot apply. There is no automatic source replacement or fake feature simulation.

## Availability and bounds

The menu combines common tags with up to 256 declared entries. A bounded reader inspects existing embedded/loaded, uncompressed TTF/OTF GSUB/GPOS FeatureLists. A declaration means only that the tag occurs in those tables: it does not prove that a lookup is active for this script, language, sample or variation. A missing declaration does not prove unsupported behavior; kerning and other mechanisms or fallback may apply. System/native fonts without an accessible asset, WOFF2, malformed/oversized data and uninspected assets explicitly report availability unknown. No proprietary fonts are added.

The preview clips safely at 512 UTF-16 units and is isolated from the surrounding shaping context. It does not reproduce canvas wrapping, paragraph spacing, list markers, decoration/paint or every cross-fragment shaping interaction. Neutral ink and a scrollable viewport keep source-sized glyphs legible. The browser may use fallback for unavailable faces or missing glyphs; the font-loading status explicitly says so. Feature differences depend on the actual font and sample; identical specimens are not evidence of unsupported features.

At most eight font assets and 14,000,000 combined data-URL characters are considered for metadata inspection (approximately 10.5 MB of base64-decoded payload before URL overhead). Each inspected asset additionally has an exact 10,000,000 decoded-byte cap; the raw table reader has the existing 20 MB font cap, 4,096 directory/feature-record caps, and table/offset bounds checks. The metadata cache holds at most 16 entries. At most eight browser face-loading requests are made for each specimen state; remaining fonts may still render but have no loading assurance. Existing feature-map (100 entries) and rich-run (10,000) validation limits also apply to edits. A full valid 100-entry source map can still compare a 101-entry local CSS candidate; applying that extra entry is atomically refused by the existing document validator.

## Verification

Core checks cover actual bundled open-license Lato, Inter and JetBrains Mono font declarations, corrupt table refusal, mixed-map preservation, empty-map inheritance, safe Unicode clipping, full-paragraph Auto direction, and Undo. Browser checks compare actual Lato ligature pixels with identical source/font/axes; exercise mixed ranges, save/reopen and Undo; inspect real effective CSS inheritance; verify unknown system/custom metadata, local specimens and RTL source direction; and refuse stale document/range/mode/visibility/candidate drafts.

UI-22-053 has a reachable font-rendered comparison workflow within these stated limits. Reference verification against Figma remains separate; this does not assert exact Figma feature-menu, font-engine or shaping-context parity.
