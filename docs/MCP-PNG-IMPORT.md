# Source MCP PNG import

The free local stdio server exposes `import_image_asset`. Supply the current revision, page ID and a canonical `data:image/png;base64,…` string. Optional name, x/y and display width create one ordinary editable page-root image layer; natural dimensions come from validated bytes and display height preserves the aspect ratio. Its image paint embeds the asset once. The saved `.oui` versions one/two use existing image fields; there is no schema migration.

This source workflow has explicit partial coverage: noninterlaced 8-bit RGB/RGBA static PNG only, at most 20 MB, 16 million pixels, 16,384 pixels per side and 4,096 chunks. Chunk structure/order, checksums, supported color metadata and canonical base64 are checked; zlib inflation is bounded by the declared scanline size, requires complete consumed input and validates every filter byte. Indexed/grayscale/16-bit/interlaced PNG, compressed color profiles/text, animation and other raster formats refuse before writing. Plain supported PNGs may include sRGB/gamma/chromaticity/pixel-density, uncompressed text, background/transparency and a suggested palette. Other project/geometry limits can refuse a smaller asset. Use the editor for other image formats.

The supported chunk ordering and uncompressed text/keyword checks follow the [W3C PNG specification](https://www.w3.org/TR/png-3/#5ChunkOrdering). This importer additionally refuses trailing unused compressed bytes, a deliberately stricter subset than permissive PNG decoders.

The tool receives bytes from its caller; it never reads an asset path, fetches a URL or starts a listener. The only writable file remains the launch-time scoped project. Existing optimistic revision checks, shared derivation/validation, bounded 50 MB project, atomic file replacement and process-local transaction Undo apply. Responses include metadata and node ID without echoing asset bytes. `read_nodes` continues to omit assets unless explicitly requested. Existing MCP SVG export restrictions are unchanged; neither raster export, live editor synchronization nor screenshots are added.

Source tests cover valid RGB/RGBA, transparent pixels, canonical bytes, malformed/truncated chunks, CRC, compressed-data bombs, invalid filters, dimensions, animation/unsupported chunks, real SDK stdio discovery/schema/redaction, stale revisions, unchanged bytes/history on failure, persisted one-step Undo, and actual editor rendering/save/reopen. Native Mac and standalone bundled-server acceptance remain deferred while downloads/builds are frozen. Source-only changes do not regenerate the archive or website.
