# Local stroke styles and primary stroke tokens

The source editor supports named local stroke styles in the Design system inspector. Create from a selection, assign to unlocked compatible layers, detach while retaining the current literal strokes, update from a selected source in Manage styles, navigate slash-name folders, and inspect linked usages. Each style captures the complete stack, including gradient/image paints, width, alignment, cap, join, miter, visibility, dashes and offsets. Legacy paths' implicit round caps/joins are materialized when capturing a new or updated style. Empty stacks also remain empty when reused. Styles propagate through the existing derived pipeline, component source synchronization, Undo, saved `.oui` documents, local library JSON and cross-document design clipboard.

Existing color and number variables can control the **first stroke's color and width**. Width now updates the actual rendered stack rather than only a legacy scalar. Other entries retain independent literal values. Caps, dash and opacity edits retain unrelated primary bindings; a literal primary color/width edit detaches the corresponding binding. Reordering/removing the primary entry detaches bindings attached to that slot. Style assignment clears competing primary tokens; binding a primary token detaches the competing stroke style. Independent bindings on every stack entry are unfinished, so UI-18-030 remains partial.

Stroke numeric controls use the shared guarded numeric field. Dash drafts validate finite nonnegative values, support Escape cancellation, and are discarded after document/page/selection/mode context changes. Inherited locks disable editing. Assignment transactions retain the existing component-controlled assignment refusal.

The additive `stroke` style kind is accepted in current version-one/version-two `.oui` documents. Stroke stacks share node/style preflight validation. Malformed style definitions refuse before editor, library or saved-file MCP mutation. Bridge source preflights stroke style definitions before creating Figma pages, transfers saved literal strokes and explicitly reports that editable definitions/style links are omitted. Source API mocks are not a real Figma desktop round trip. Figma still shares the first stroke geometry across multiple paints; unsupported geometry differences retain the existing omission report.

Source regressions cover canonical legacy capture/update, complete and empty stacks, imported scalar-only styles, conflicts and inherited locks, aliases/modes/removal, literal binding detachment, library/clipboard identity remapping, asset usages, malformed-file atomic refusal, actual rendered SVG stroke attributes, guarded drafts, save and Undo. Exact Figma reference acceptance and native WKWebView checks remain pending. No download, archive, production or native build is generated by these changes.
