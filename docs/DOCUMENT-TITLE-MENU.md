# Document title actions

The title in the editor's top bar opens a local **Document actions** menu. It uses the existing Rename, File information, Save/Save As, named local version/history, Open, image/SVG import, artwork export, Figma interchange and Back to files commands. Labels and shortcut hints come from the same command registry as the File menu. The neighboring New design button and sidebar file rename entry remain available. Double-clicking the top title opens the existing rename dialog; this does not replace the app's current rename workflow with another document schema or editing path.

The title button exposes its filename, menu relationship and expanded state to assistive technology. Enter/Space or a click opens it; Arrow Down/Up opens at the first/last item. Inside the menu, Arrow keys wrap, Home/End select boundaries, and prefix typing finds labels (repeated letters cycle matches). Enter/Space runs the active action. Escape restores the title button; Tab/Shift-Tab exits to the next/previous visible control. Outside clicks dismiss without taking focus from the clicked control. The menu closes on document changes, an opened modal, Home, hidden UI, window blur or resize.

Canvas typing, deletion and nudge keys are contained while the menu owns keyboard focus. Existing registered File shortcuts, including Save, Save As and Open, continue to dispatch their normal file commands. Other editor shortcuts retain their normal behavior after the menu closes. Rename and File information focus their existing dialogs, with focus returning to the title after that immediate dialog closes. The owned named-version/history dialog chain also returns focus to the title; unrelated modal changes clear that return target. Menu actions recheck the captured document identity/reference before invocation; an old menu cannot operate on a newly loaded project.

Hydration still gates the whole editor, so the title menu is unavailable until recovery/native bootstrap finishes. An existing modal disables the title trigger. No editable permission system is invented: File information's read-only identity/workspace facts and existing native save/open checks remain in their current command paths. Native Open still delegates window creation/focus to the Mac shell; the menu does not take over native document ownership or add filesystem/clipboard IPC.

This feature does not supply cloud sharing, account/team controls, private Figma links, publishing, file ownership or direct binary `.fig` compatibility. Version history remains local to the device; portable `.oui` backups use the existing Save workflow. Exact Figma reference-menu parity remains pending.

`tests/title-menu.test.ts` checks the registered local-command contract and normalized wrapping prefix matches. `tests/e2e/document-title-menu.spec.ts` checks real keyboard/focus behavior, unchanged artwork/history, rename/save/Undo, native Save/Save As/Open transport fixtures, held hydration and stale document changes. Native transport fixtures are browser checks, not a Mac shell runtime gate.
