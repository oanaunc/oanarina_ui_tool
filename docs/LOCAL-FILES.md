# Local file browser

Home browses projects stored in this app on this Mac. It has Recent, All files, Drafts, Starred, Pinned, Archive and Trash views. Search file titles, filter by workspace type or local folder, and choose a thumbnail grid or compact list. Sort by name, modified time or last opened time. Pinned files appear first. Grid/list, sort and type preferences persist on this device.

Create and rename flat local folders, move files between folders or Drafts, and remove a folder without removing its files. The folder is organizational metadata; it does not move exported files in Finder. Removing a folder moves all its files, including archived and trashed files, to Drafts. Up to 200 folders are supported.

Use a file's **…** button or right-click for Open, Rename, Duplicate, Move, Star, Pin, Archive and Trash. Duplicate creates a new document identity and an independent content copy with its internal references intact. It keeps the folder, starts unstarred/unpinned/unarchived, and does not copy named versions. Rename, move and status changes expose a Home undo action. Undo checks organization revisions rather than overwriting a later change made in another window. Undo is session-local and one action deep; normal editor undo remains separate.

Trash retains file content until explicitly restored or permanently removed. Restore returns the file to its original folder and clears its archive flag. Permanent deletion requires a separate confirmation, removes the file and its named local versions, and cannot be undone. A file open in the current browser editor or any native editor window must be closed before permanent removal. A minimal ID tombstone prevents a late autosave from recreating it. Organization supports up to 10,000 file records, including tombstones.

Explicitly opening an exported `.oui` backup validates it completely, then restores that file identity to local storage even if its former local copy was permanently removed. This keeps the file association and internal references intact. Trash/deletion flags are cleared only for that deliberate file-open action; ordinary autosave and session recovery cannot revive a deleted project. A restored backup keeps its existing local folder when available, clears archive if it was in Trash, and does not recover permanently removed named versions. A failed validation leaves the tombstone and library unchanged.

If local storage is unavailable, full or has invalid organization data, a valid saved file can still open for editing in memory. A warning asks you to save a `.oui` backup and reopen to retry local storage. Failed storage writes leave the library and any deletion flags unchanged; recovery and Home availability are not guaranteed for that in-memory session. Invalid or oversized file input is rejected instead of using this fallback.

Browser **File → Open project** also retains the outgoing editor's latest changes before replacing it, without waiting for the autosave debounce. If unsaved edits cannot be retained, save a `.oui` backup before opening another file. The startup Home sample is not written merely because you select an incoming project. A cancelled or superseded open aborts its pending recovery writes. Supported binary `.fig` Design files use the [local importer](FIG-IMPORT.md) and become separate Forma projects.

**Import projects** adds `.oui` / JSON projects to the library without replacing the current editor. Each imported project gets a fresh document identity, so importing an existing file cannot overwrite the local original. Every file in a batch is parsed and validated before any write. The write is atomic: a malformed file or a failed transaction does not leave a partially imported batch. Import supports 1–20 projects, at most 50 MB per project and 100 MB per batch. Undo moves imported copies to Trash.

Native Home opens a saved project through the Mac document-window bridge. Browser Home opens it in the current editor. The native bridge is tested separately; a browser bridge regression verifies routing and open-file protection, not a real AppKit window round trip.

Projects and organization use IndexedDB. Metadata is stored separately from `.oui` documents, preserving file compatibility. Writes update metadata transactionally, and organization notifications refresh other app windows sharing the same local storage. This is local storage rather than a cloud account, team, ownership system or collaboration service. Export `.oui` backups: clearing app/browser storage removes the local library. Other browser tabs editing the same project still use last-writer behavior for project content; revision checks protect organization changes, not collaborative document editing.

Validation: `tests/file-browser.test.ts` covers metadata validation, independent document copies including whiteboards and slides, filtering, ordering and preferences. `tests/e2e/home-files.spec.ts` exercises actual file input, Home actions, persistence, editor opening/renaming, native routing, atomic import failures, serialized metadata transactions, stale revision rejection, Trash recovery, version removal and tombstones.

File metadata can also hold a local owner label. Owner labels, Copy file link and Open in new tab are described in docs/EDITOR-SHELL.md.
