# Local comment links

Open **View → Comments** and choose **Copy local comment link** on a thread. Paste that reference into **Open local comment link** in the same dialog and choose **Go to linked comment**. This follows the existing local section-link pattern: `forma-comment:` contains only percent-encoded file, page and thread identifiers. It creates no public hosting, sharing permission, OS URL handler, network request or automatic file opening. Open the matching `.oui` file first. Links do not include comment text, authors, page titles or filesystem paths; identifiers still identify their saved project.

Opening a valid reference selects its page and available anchor layer, centers the actual derived pin position, returns to Design with Motion closed, clears local thread filters and focuses the correct result page. Resolved threads work. Repeatedly opening the same link focuses its heading again. Missing anchors use the existing disclosed saved-position fallback. The document, original thread metadata and Undo history stay unchanged. Ordinary save/reopen preserves the identities a link references; page duplication creates new thread identities.

Links are limited to 4,096 encoded characters and three nonempty identifiers of up to 512 characters without controls. Foreign files, malformed encodings, deleted threads, ambiguous legacy identities and targets outside the first 10,000 indexed comments refuse before navigation. Reply-specific targets, public/browser hyperlinks, cross-file lookup and prototype sharing remain unfinished; requirement UI-36-017 stays partial. The separate FigJam and collaboration requirements are unchanged.

Copy uses plain text. Clipboard refusal exposes a selected read-only link for standard Command-C on each retry. Source and immutable local-list/input receipts reject retained handlers after context changes or same-event away/back cycles. A new copy operation owns its result UI only after current source and local-list validation. Independent review found that publishing its token before validation allowed an invalid retained text-copy handler to cancel a newer valid completion; the corrected order has a dedicated regression. Stale asynchronous clipboard results cannot replace current fallback/status UI. Native Enter/Space controls and modal focus work within short windows at 125% UI scale.

Validation: 28 focused comment/link core checks, all 31 new and adjacent comment browser cases, and the editor TypeScript check pass. Checks include real clipboard contents/refusal, repeated fallback focus, same-event draft/source/filter cycles with fresh recovery, paged cross-page anchored navigation, foreign/deleted references, camera coordinates and document/history invariance. No app/native build, package, release or standalone archive refresh is performed. Native OS clipboard and exact Figma reference acceptance remain separate.
