# Local asset usage and style workflows

Forma’s Resources → **Asset usage and unused candidates…** opens a read-only local reference audit. It is also reachable from the Design system inspector and both local style/variable managers; each style has **Find usages**. This is a source implementation, not a Figma reference-verification or native release acceptance result.

The audit indexes local variables and collections, paint/text/effect styles, layout guide styles and main components across all pages. It follows saved variable aliases in every mode and shows direct and indirect usage locations, the originating mode, and one shortest alias path. Search accepts asset names, descriptions, folders, page/layer names and usage labels. Type/status/folder/page filters and paginated locations help inspect larger files. **Show on canvas** selects the real layer and page; hidden hierarchy remains hidden and the selection is identified in Layers. Slides data is indexed, but canvas navigation explicitly refuses Slides targets.

Saved dependencies include hidden, locked and generated layers; disabled reactions; explicit collection modes; variant membership/defaults; preferred component suggestions; default swaps and instance-swap properties. Prototype expression references are parsed as expressions rather than executed: bare variable names and literal `var("name")` calls are indexed. Ambiguous names retain all matching potential dependencies. Dynamic/unparseable lookups withhold “No saved references” for variables. Known text-property literals are not component dependencies merely because their strings match a component ID. Unknown instance properties matching component IDs are explicitly retained as potential dependencies.

**No saved references** means this complete scan found no incoming saved link for that asset type. It is a review candidate, not proof an asset should be deleted. There is no delete-unused command. Intentional library/export definitions can have no local consumers. Structural collection/variant membership and inactive suggestions count even when no visible screen uses them. Missing and wrong-kind references are shown without silently rebinding data; an existing wrong-kind definition remains a potential dependency.

The index caps reference count at 100,000 and logical work at 500,000 steps. Reaching either limit marks the scan incomplete and withholds every unreferenced status. Alias traversal uses predecessor links rather than enumerating paths. Display paths are abbreviated after 64 segments per row or 100,000 total displayed segments, while traversal/search and the full set of indexed reference locations remain available. JSON reports contain the indexed definitions/reference metadata and uncertainty warnings, not project artwork/media bytes. They are snapshots, not importable asset libraries.

External consumers, copied/literal colors, fonts and copied motion presets are outside this linked-asset audit. A report cannot prove absence of those uses. No document changes, history entries or hidden-layer visibility changes are made by inspection/navigation/report export. No additional document schema, filesystem access or native IPC was introduced.

## Existing local styles verified and corrected

Text styles are created from an actual selected text layer in the Design system inspector, applied with its **Text style** selector, edited in Resources → **Local design styles…**, and detached with **No style** while preserving the current values. The manager edits family/size directly and **Update style from selection** copies the full shared text style field list into the existing style identity. Consumers update through the normal document derivation; source edits detach that source first. Incompatible non-text selections and stale sources are refused. Rejected fields restore the actual saved value; pending manager drafts cancel on document/selection/context changes before blur. Style edits participate in Undo and persist in .oui versions 1 and 2.

Slash-separated local style names now have a folder dropdown and breadcrumb navigation. Folder matching uses complete path segments, supports root names and nested prefixes, and preserves the original names and IDs. Rename remains an ordinary undoable style edit. These are naming folders rather than separate persisted folder objects. Library import conflict resolution is a separate behavior and is not completed by this navigation.

Local layout guide styles already have reachable creation, application, update-from-selection, editing/deletion and detachment paths in frame inspectors. The existing browser regression verifies updating linked consumers and retaining guide values on detachment; the asset audit additionally indexes guide style assignments. These existing implementations are distinct from Figma parity verification.

## Validation

Core tests in `tests/asset-usage.test.ts` cover all-mode alias paths, hidden/cross-page usages, prototype AST/dynamic uncertainty, component dependency channels, wrong-kind/missing definitions, budgets/cycles, a 5,000-variable chain, literal ID collisions, navigation, exact folder prefixes, text-style propagation/Undo/version compatibility, and atomic refusal of incompatible/stale updates.

Browser tests in `tests/e2e/asset-usage.spec.ts` exercise real menu/inspector entry points, cross-page hidden selection, read-only reports, conservative uncertain/unused lists, component navigation, exact folder navigation, rejected field restoration, text-style creation/update/detach/Undo/save/reopen, and stale draft cancellation. Existing design-system/style and guide browser checks cover the adjacent shared controls.
