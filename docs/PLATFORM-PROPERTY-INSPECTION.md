# iOS and Android property inspection

Select a layer and switch to **Inspect**. **Native platform properties** presents a read-only iOS or Android reference alongside the existing CSS and design-system inspection. Choose the platform, explicitly set canvas units per logical unit, search rows and copy the filtered reference with its assumptions and limits. Changing these controls does not edit the project or create Undo history.

Geometry, page coordinates, rotation, layer opacity, visibility, box radii and local scale are reported. A supported single solid fill or stroke reports its saved sRGB channels and paint alpha separately from layer opacity. iOS colors use a clearly labeled RRGGBBAA reference notation; this hex notation is not a UIKit initializer or generated native code. Android colors use AARRGGBB order. Base text includes family, numeric weight/style, logical size, authored line-box target, spacing/alignment/direction. Android letter spacing is expressed in em. Auto-layout padding/gaps describe saved intent.

One canvas unit maps to one point or dp by default. The ratio is a user-controlled design interpretation, not an inferred physical display density. iOS fonts use points. Android text uses baseline sp at font scale one, after which Android applies user font-size preferences. Screen scale, Dynamic Type, runtime font scaling, platform font availability, native constraints and actual native text metrics are not inferred. No project color profile is added or claimed.

The existing **Value source** selector controls sampled Motion versus base properties; the reference identifies which source it uses. Multi-selection can choose one inspected layer. Complex fill/stroke stacks, vector paths, masks, clipping, effects, media and specialized rich typography are disclosed rather than replaced with an invented native equivalent. There is no runnable code generation, UIKit/Compose project export, native resource installation or device preview. UI-41-006 and UI-41-007 therefore remain partial toward complete native handoff parity.

Reports are bounded to a small fixed property set and truncate family/name labels. Embedded artwork bytes, literal text body and private IDs are omitted. The conversion ratio accepts 0.01–1,000 units and rejects empty/nonfinite input. Copy validates permanent global source context and synchronous parent/local candidate receipts before touching the clipboard; mode cycles and retained source/option callbacks refuse while fresh controls recover. If clipboard writing is unavailable, displayed text remains selectable. Enter/Space activate the section's native button without the canvas swallowing Space as a pan key.

Nine headless tests cover logical unit conversion, color ordering and alpha, typography, supported/unsupported shapes, layout/transforms, invalid values and bounded copies. Nineteen actual browser checks (ten new and nine existing inspection cases) cover real clipboard text, filtering, save/no-history, Motion/base selection, stale source/options, selection switching, late copy success/failure, same-event source cycles, denied clipboard and 125% short-window Space activation. A review found and corrected duplicate React sibling keys on inspected-layer changes; platform rows have their own CSS class so existing metadata pagination remains scoped to its 200-row budget. Independent review also corrected zero-scalar-width edge-stroke detection, late clipboard status ownership, reactive source receipts and overflow-safe formatting for valid extreme coordinates. These are shared source/browser checks, without a new native build or exact Figma native-property reference acceptance.

Primary unit and color references consulted:

- [Apple UIScreen scale](https://developer.apple.com/documentation/uikit/uiscreen/scale) distinguishes logical coordinates and device scale.
- [Apple UIColor components](https://developer.apple.com/documentation/uikit/uicolor/init(red:green:blue:alpha:)) documents RGB components and alpha.
- [Android grids and units](https://developer.android.com/design/ui/mobile/guides/layout-and-content/grids-and-units) describes dp and sp roles.
- [Android pixel densities](https://developer.android.com/training/multiscreen/screendensities) explains layout units versus physical pixels.
- [Android Color](https://developer.android.com/reference/android/graphics/Color.html) documents the AARRGGBB string order.
