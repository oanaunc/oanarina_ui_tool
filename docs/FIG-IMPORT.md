# Open a local Figma Design file

In the Mac app or browser editor, choose **File → Open project…**, then select a supported `.fig` file. The Mac Open panel and Finder **Open With → Forma** use the same import path. Forma registers as an alternate viewer/importer; it does not take ownership of Figma's file type.

Forma decodes the selected archive locally and validates the converted document and embedded raster pixels before opening it. The original file is never served through the local HTTP server or uploaded by the importer. Additional font downloads follow the existing font-library settings and are separate from document decoding. The source archive thumbnail is not used as a substitute for the document.

After import, review **Figma import report**, then edit the converted project. Save a `.oui` copy. On Mac the imported project starts dirty, has no source-file save binding, and its first Save requires a destination. Cancelling Save keeps the imported document open and unsaved. Native saves refuse a `.fig` destination. Reopening an already imported source focuses its existing window. Recovery uses the converted local project, not a writeable `.fig` binding.

## Supported subset and reductions

- Public Design pages, supported shapes/frames/groups, local transforms, order, opacity, visibility and supported paints, strokes and effects.
- Referenced embedded static PNG, JPEG, GIF and WebP assets. Encoded dimensions are checked before pixel decoding, and pixels are decoded before the file opens, with an 8,192-pixel edge limit, 16-million-pixel surface limit, 20 MB encoded-image limit and 64-million unique-pixel budget. An image that fails any of these, or arrives damaged in the archive, becomes a marked placeholder and is reported. The rest of the file still opens.
- A repeated image counts once toward the project limit and is saved once. See [Repeated images](#repeated-images).
- Editable text with supported font and paragraph properties, including lists with their levels, start numbers, spacing and hanging markers, leading trim, hanging quotation marks and punctuation, underline style, thickness, offset, color and skip ink. When source glyph geometry is available and supported, an additive saved outline preserves its original appearance. Rich text has no such outline, so it keeps the file's own line breaks and stored size, and keeps its auto-resize setting. Editing text, typography, rich-text styling or text layout invalidates what was saved and uses the actual editable text with available fonts. Moving the layer and changing its overall color/opacity remain ordinary edits.
- Text case stays a live setting for a whole layer or part of one, so the stored characters stay as typed. Uppercase, lowercase and title case come back as Forma's Letter case control, and title case leaves the other letters alone, as CSS capitalize does. Small caps stay live, and forced small caps become lowercase shown in small caps. A checklist line stays a checklist line with its checked state. Hanging punctuation comes in as its own setting: quotation marks at paragraph ends, and periods, commas, dashes, brackets and bullets at every line edge. A line with an explicit bidi control, and any line after it in that paragraph, keeps ordinary placement.
- Main components stay main components, and instances stay live instances with their overrides. Nested overrides follow their full source path. Editing a main reaches every unoverridden copy. Mains kept outside the visible pages (library copies, soft-deleted mains) are added to an **Imported components** page so their instances keep working.
- Component sets become variant sets, in their stored property order. Text, Boolean and instance-swap properties become component properties when one layer consumes them.
- Auto layout, grid auto layout with its tracks, gaps, spans and cell alignment, constraints, min and max sizes, and absolute children stay live. Local paint, text and effect styles and variable collections with every mode become real Forma styles and variables, linked where the layer agrees with them.
- A link to a library style or variable follows its key and version to the copy the file holds. A key with no copy keeps the layer's own values and is reported.
- Variables stay bound on padding per side, single corners, wrap and grid gaps, min and max sizes, letter and paragraph spacing, paragraph indent, font family, line height in pixels or percent, each border side, every shadow and blur field, gradient stops, paint opacity, and every fill and stroke, as well as the fields bound before. An entry in a stack binds through its own id, and Design system lists each one while it is bound, so it can be changed or set back to a literal. A binding stays a plain value when the variable and the stored value disagree, when Forma has no such field, when Auto line height is on, or when a paint Forma could not keep shifts the stack. A linked style replaces its stack, so bindings on that stack stay plain.
- A resized instance with no stored position for a layer places it by that layer's constraints and auto layout, the way an edit would. Stored positions win. A group that takes a new size from its constraint scales its layers, as resizing the group does, and their strokes, radii and type keep their values.
- Background blur is kept on independent rectangles and ellipses that share a parent, over a known backdrop, on pages without a prototype, because Forma can't draw it elsewhere and can't play a page that has one. Each blurs what lies beneath it, the earlier ones included, up to 16 in a file. Radii stop at 128. Others are omitted and reported. Progressive blur keeps its ramp up to Forma's budgets, then falls back to a uniform blur. A progressive background blur is uniform.
- Vector anchors, masks, image crops, gradient handles, corner smoothing, independent stroke weights, mixed text ranges and prototype links and flows map to native Forma data. Crops that are stretched, rotated or sheared keep their exact placement, and the crop tool replaces it with a plain crop on the first drag. Other exports draw that placement in SVG, raster and PDF, while PowerPoint and site export treat it as an ordinary crop.
- A flattened vector whose regions have their own fills becomes one layer per run of regions, with any stroke on its own layer above. Each fill layer keeps the anchors of its own regions, or its finished outline if they can't be matched to its fills. A mask stays one shape with the layer fill.
- Arrowheads set on a vector's end points or on the layer reach every open path, in the styles Forma has, and **Line and arrow** edits each path. Their size comes from `strokeCapSize`, on the point first and then the layer: pixels as stored, and raw or percent against the stroke weight. A path with no stored size estimates it from the stroke weight, and a path with a different size at each end uses the larger. Reading raw and percent that way is a judgment, not something a real file has shown. A line with a stored outline keeps that outline as a filled vector.
- Set-variable and conditional prototype actions run in Forma, with formulas turned into Forma expressions that name variables by id. An action whose value or condition Forma can't state is left out and reported, including the whole conditional, so a condition it can't read never becomes an else. Set-mode and media actions are reported, not imported.
- Spec pages become Spec layers you edit block by block, with headings, paragraphs, lists, tables and code in reading order. See [Spec blocks](#spec-blocks) and [Spec pages](SPEC-PAGES.md).

The report lists what stayed live and every known reduction; it is not a guarantee of complete appearance or behavior parity. Stored positions win over live structure: before the file opens, Forma runs its own edit pipeline on a copy, and any instance, auto layout frame, Boolean or style link that would move or change the stored artwork is dropped to plain layers and reported, so the first edit cannot rearrange the file. Unsupported containers or malformed input fail before replacing the current artwork; a missing or unreadable image stays a marked placeholder you can replace, and only cancelling stops the check.

**Evidence limit.** Every test here uses generated files. The field names come from what the existing mapper already reads and from public format research, not from a Figma schema the tests can check against. Where a real file names a field differently, that feature falls back to the plain result and the rest of the import is unaffected. A real-file comparison is still pending. Compatibility with every `.fig` file is not claimed.

Files and converted projects must be smaller than 50 MB, counting each repeated image once, at most 20,000 layers per page and 60,000 in total. [Container limits](FIG-CONTAINER.md) also apply. A new File Open supersedes and aborts the previous operation; editing or changing the current document/page cancels a pending browser import, including a queued local recovery transaction. Failed or cancelled imports must not replace the active recovery identity.

Binary `.fig` export is not implemented and stays planned: a file only Forma could read would be a `.oui` wearing the wrong extension, and without a reference schema nothing here could show that Figma opens it. Use `.oui` for Forma projects, the supported [Figma Bridge](../figma-plugin/README.md) subset for editable return transfers, or SVG for visual exchange. A successful import is not a full-fidelity Figma round trip.

## Validation boundary

Committed tests use generated synthetic schemas, archives and artwork. Container, scene, raster, edit/undo, save/reopen, cancellation and native lifecycle checks are separate gates. Private user archives, decoded content, images, identifiers and comparison screenshots remain local and are not public fixtures. A low-resolution archive thumbnail can assist a local comparison but does not establish exact live-Figma acceptance.

## Repeated images

A project holds a repeated image once. In memory every use shares one string, so Undo and copies don't add to it, and a saved `.oui` writes the data on the first use and a key on the later ones. Parsing restores every use before anything else reads the document. The 50 MB project limit counts the saved form everywhere it's checked.

An imported file stops at 340 MB of image data once every use is counted, because some work still reads each use as a full data URL. Browser recovery stores the full form, so a project near that size may open in memory only, with the usual warning. An older Forma opens such a project with the later uses as empty placeholders. Only images in layer fills and strokes are shared. Spec images aren't.

## Pasting a copied selection

On Mac, Paste looks in the clipboard's HTML for a base64 message that starts with the `fig-kiwi` header. A match goes through the same worker, mapper, validation and settle pass as a `.fig` file, behind the import panel's Cancel, and lands as one Undo step. Layers that arrive without their page gain one, and mains they need arrive with them. Image bytes are not expected in the clipboard, so images stay marked placeholders.

**Evidence limit.** This shape comes from public third-party research. Tests use payloads written here, in the same synthetic schema as the `.fig` fixtures, and no real clipboard capture has been decoded. If a real copy is laid out differently, Paste reports that it could not read it and nothing changes. The dependable route remains Copy as SVG in the source app, which Paste already imports through SVG review.

Copying out of Forma writes SVG markup as plain text and as an SVG flavor, through **Copy selection as SVG**. Whether another app accepts that paste has not been tested here. Forma does not write a `fig-kiwi` clipboard payload, because no reference schema exists here to show that anything else could read it.

## Spec blocks

A spec page is a `SPEC_BLOCK` with `specBlockType` `DOCUMENT`, and its child blocks hold the content. Each child names its kind in `specBlockType`: headings, paragraphs, ordered, unordered and to-do list items, code, quotes, rules, tables, images, embeds and embedded canvases. Its words are in `specBlockContent`, a plain-text edit history.

Forma replays that history from `historyOpsWithLoc` and `historyStringContentBuffer`, or uses `snapshotText` when stored. Inline `**bold**`, `*italic*`, `~~strike~~`, `` `code` `` and `[links](https://example.com)` are stored as literal markdown and become formatting.

The page becomes one Spec layer holding its blocks in stored order. It keeps its stored size as a minimum height and grows as text is added. Headings use fixed sizes by level. Interior blank lines stay as empty lines, and trailing ones are dropped.

If any block's history cannot be proven, for example a range that falls outside the text, the whole page keeps its stored preview image and the report says so. Forma does not show partial or wrong words. An embedded canvas's stored layers land in a frame beside the page, and its block shows that frame live. One with no stored layers shows as an empty block and is reported. Images or embeds without a usable reference are left out and reported.

**What was checked.** The format comes from the schema embedded in a real file, whose four pages of 54 blocks imported with their words matching the stored previews. That file holds headings, paragraphs and bullet lists only. Tables, code, quotes, rules, to-do items, images, embeds and embedded canvases follow the schema's field names and are tested with fixtures written here, not real files. The tests in this repository use only self-authored files.

Other unknown layers, and spec blocks without `specBlockType`, are read by shape: real child layers, then `textData`, then structured blocks under any field name, then a strict Yjs update, then printable sentences in byte fields. Those routes are guesses tested only with fixtures written here. A layer with no readable text keeps its preview as a flat image, and one with no text and no preview is omitted and reported.

## Names checked against a real file

Field and enum names were corrected against the schema a real file embeds, after a comparison with FigCraft's importer (MIT or Apache-2.0) pointed at them: `mask`, `count`, `miterLimit`, `resizeToFit`, `SWAP_STATE`, `MOUSE_IN`, `MOUSE_OUT`, `DRAG`, `GENTLE_SPRING`, and the overlay fields, which sit on the frame that opens. No code was copied. These names are confirmed to exist in the format, but most of them aren't used in the one real file tested, so how they behave comes from `tests/fig-real-format.test.ts`, `tests/fig-import-fidelity.test.ts` and `tests/fig-import-finish.test.ts`, whose fixtures are written here. Grids, lists, checklists, text case, library keys, crops, multi-color vectors, arrowheads and their sizes, blurs, effect and gradient bindings and variable actions in particular appear in no real file tested so far. The real file's only variable consumption is a fill color.

`tests/fig-schema-names.test.ts` keeps this true. The type checker lists every field and enum value the importer reads, and the test compares them with the schema inside a real file, found through `FORMA_REFERENCE_FILE` or at `build/fig-import-reference/canvas.fig`. A checked list in the repository fails any name that was never verified, even on a machine with no real file. After adding a name, run the test with `FORMA_RECORD_NAMES=1` beside a real file to record it. It found `overflowDirection`, `LAYER_BLUR`, the `CROP` image mode and four easing names, none of which exist in the format, and they are gone.

`{100, PERCENT}` means Auto line height. 49 of 55 text layers in the real file use it, and Forma takes the height from the lines the file already laid out, or 1.2 when there are none. A frame with no `stackPrimarySizing` hugs its primary axis. Infinity means no maximum.

Files past Forma's limits of 20,000 layers on a page or 60,000 in a file now import up to the limit and report what was left out. A repeated node ID keeps the last copy, and a layer with a missing parent is left out and reported.
