# Auto layout source workflows

These are local, reachable editor workflows, not a claim of complete Figma parity. Figma reference verification remains pending. This change generates no native build, resource ZIP or release.

| Register entry | Source behavior and remaining limits |
| --- | --- |
| UI-23-021 Aspect ratio in layout | An aspect-locked item keeps its current ratio when its main or cross axis fills/stretches. Dual fill fits the ratio inside the allocated slot; single-axis fill drives the other dimension. Shared linear/grid layout, source components, instances, saved files and headless MCP use the same solver. Hard min/max limits take precedence when no size can satisfy both the ratio and the limits. An optional derived `layoutAspectRatio` retains the intended ratio across zero-size collapse, incompatible hard-limit passes and reopening. Explicit manual size/lock edits refresh it. Locking content-sized text explicitly fixes the current box in the same Undo transaction; existing imported auto-sized text keeps its content-sizing precedence until explicitly relocked. |
| UI-24-008 Horizontal padding | A paired control changes left and right padding together, preserving top/bottom. An unequal-edge note states current values before either pair is edited. Existing independent and uniform controls remain available. |
| UI-24-009 Vertical padding | A paired control changes top and bottom together, preserving left/right, with the same independent/uniform alternatives. |
| UI-24-027 Reverse stacking order | “First child on top” reverses painting, not layout/layer order. Canvas hit order and SVG/PNG rendering agree. Existing mask runs retain their original mask membership while groups and their masked artwork reverse painting order. |
| UI-24-028 Baseline alignment — partial | First-line SVG baselines extend through nested containers, including rotated, flipped and scaled ones: the first line's start point is carried through each transform into the row's axes. Baselines use the app's own text measurement, so complete native font metric equivalence remains unfinished. |
| UI-24-029 Stroke included in layout — partial | An explicit toggle includes visible inside parent stroke insets and center/outside child stroke extents in linear and grid sizing, gap, padding, fill allocation and wrap breaks. Hidden/zero-opacity paints contribute no stroke extent. Transformed children use the bounding box of their stroke box, and arrowheads past the line box widen its symmetric extent. Miter tips on non-rectangular shapes and Figma equivalence remain unfinished. Shadows are excluded. |
| UI-24-034 Insert child into auto layout | An explicit inspector workflow inserts a rectangle, text layer or frame before a chosen direct sibling or after the last sibling's subtree. Shared layout immediately places it; one undo removes it. Insertion rejects inherited locks and generated instance hierarchies. This control does not claim arbitrary remote components or all drag-insertion affordances. |
| UI-25-025 Wrap direction | Rows may stack wrap lines top-to-bottom or bottom-to-top; columns may advance left-to-right or right-to-left. Primary child order and layer order remain stable. |
| UI-25-026 Wrap alignment | Start, center, end, stretch, space-between, space-around and space-evenly align wrap lines in the fixed cross-axis space. Per-item cross-axis alignment applies inside each line. A hugging cross axis uses natural line extents and gaps. |

Padding, wrap, stroke and stacking are additive `.oui` fields or reuse existing fields. Their validators run for both imports and editor transactions. Layout/sizing/aspect inspector edits check live target context and inherited locks; generated instance descendants use their main component. Motion disables these inspector controls because they edit base layout. Root instance metadata is tracked as an override and survives synchronization/reset/undo. Paired numeric controls use the shared draft/gesture cancellation behavior, including native selection changes to equal-valued targets.

The optional new fields are `layoutStacking`, `layoutIncludeStroke`, `wrapDirection`, `wrapAlign` and derived `layoutAspectRatio`. Unlocking the aspect ratio clears its hint. Available MCP node operations expose the same fields and validation. No required schema or document version changed.

SVG and raster exports use actual shared layout geometry and painting order. Editable Figma Bridge preflight validates the new fields and explicitly reports them as omitted. Native Figma auto layout may arrange transferred children differently. API-contract mock checks do not establish a real desktop plugin round trip. Generated Dev CSS is not claimed to faithfully reproduce these layout behaviors.

Validation includes 23 new core tests, nine new browser interaction checks, two existing layout browser checks, and a headless MCP regression. The browser checks include actual exported PNG pixels, overlapping canvas hit order, geometry, sibling insertion, save/reopen/undo, malformed import refusal, inherited locks and native draft cancellation. Source TypeScript and MCP TypeScript compile checks pass. The full source core suite passes 901 tests in 83 files; the direct source MCP project suite passes 23 tests. Resource archive byte-parity validation remains deferred because downloadable archives are frozen under the user's no-build/package instruction.

## Dragging children on the canvas

Dragging a child inside a horizontal or vertical auto layout, including wrapped rows, shows an insertion line in the gap under the pointer. Sibling midpoints pick the slot, with the dragged layers excluded, and wrapped rows are chosen by cross position. Release reorders the siblings once and the shared reflow places them, so one Undo restores the order. A multiple selection of siblings moves as one block in stored order. Releasing outside the container or in the same slot, and Escape, leave the order and the history unchanged.

The free move stays for absolute-position children, grid layouts, reverse-wrapped rows, rotated siblings, locked layers, instance children and Motion. Dragging a child out of its container does not reparent it, and siblings do not slide aside during the drag: the insertion line is the only preview.

## Rotated and scaled children

Linear, wrapped and grid layouts place a child by the bounding box of its rotation and scale, around its center, so a chevron turned 90° takes the space it visibly occupies, and hug, alignment, gaps and wrap breaks all use that box. Fill now works on the same box: the child takes the local size whose rotated, scaled box matches its allocation, which at a quarter turn means Fill moves to the local axis that shows, and local minimum and maximum sizes convert to parent-axis extents. At 45° one box extent cannot set two axes, so Fill on both axes shares the smaller. Layout passes grow with nesting depth, up to 256, and a layout that flips between two states stops where it always did. Before this change an axis set to Fill kept the size layout assigned and is measured unrotated. A layout saved with a rotated child updates to this placement the next time that page is edited. Untransformed layouts are unchanged. Validation: `tests/layout-transformed-children.test.ts`.
