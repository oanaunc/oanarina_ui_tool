# Whiteboard code blocks

Open a Whiteboard and choose **Code block** in its existing toolbar. **Add code block** places a real clipped frame, a language header and a text body at the visible canvas center. Select the frame or either owned text child to reopen its editor. The initial typeface is the bundled open-license JetBrains Mono, with a monospace fallback. Names do not identify logical code blocks.

The panel edits literal source, a language label, card width/height, background, text size and text color. **Apply code block** commits all accepted changes together with ordinary Undo. **Discard changes** discards the local draft. Code-only edits preserve custom paints, linked typography and geometry bindings; changed hex fields intentionally replace their respective paint stacks. Edited channels detach their competing local style/variable bindings, while unrelated channels remain intact. A post-derivation check refuses a conflicting geometry/style controller before publication. An unchanged Apply does not create a history entry.

The body’s ordinary `text` field is the canonical source. Generic text edits go through the same length validation as panel edits. `<script>`, HTML and other source remain literal text; nothing executes, fetches, installs dependencies or calls an external service. **Copy code** copies the current literal draft through the existing browser text clipboard API; when unavailable, a selectable copy field is shown. Copy completion cannot modify a replacement panel. This adds no native clipboard permission or IPC surface.

New code blocks are colored by language. **Color code by language** in the panel turns it off or on for a block. Coloring is a bounded lexical pass over keywords, strings, comments, numbers, calls, types, tags and attributes, for each language in the list except Plain text, and the palette follows the card background. It is written as ordinary text ranges, so the canvas, exports, clipboard and transfers carry it with no special case, and source stays literal. While coloring is on, the ranges are derived from the source, so manual range styling on the body is replaced at the next edit. Files without the setting are unchanged, and older Forma builds refuse a file with it. Forma does not parse, execute, complete, format or detect languages, and has no source-file import or export environment. Long lines use Forma’s existing text wrapping and tabs use the shared text renderer; raw source retains its original whitespace. Fixed body/header insets follow the frame in its own axes. Frame transforms, ordinary ancestor rotations/reflections/scales, masks and clips use the existing shared artwork renderer. New blocks use stretch constraints for live frame-resize previews. Vertical overflow is clipped; this is not an internally scrolling code editor.

The language header is derived from the selected language. Change it in the Code block panel; directly replacing its text is recomputed. Body/header layout positions and sizes follow their owning frame. Convert to ordinary layers before independently changing those controlled fields, enabling automatic text sizing/auto layout, or placing the object inside a main component/instance. **Convert to ordinary layers** removes only the logical record and is undoable. Ordinary typography and paint editing remain available. Imported code blocks require a frame and two distinct, fixed-size text children on one page, outside component/instance ancestry. New authoring controls offer 80–4,000-unit card sizes and 6–96-unit text; ordinary canvas geometry keeps the existing document limits.

`whiteboard.codeBlocks` is optional in `.oui` versions one and two. Nonempty logical records belong only to actual Whiteboard documents; importing them under another workspace refuses instead of installing a hidden controller. Older documents without this field are unchanged; no migration or new document version is required. Each record contains only `{id, frameId, textId, labelId, language}`. Records cannot claim layers already owned by another Whiteboard logical object. There are at most 512 records, 50,000 UTF-16 units per source body, and 1,000,000 total source units. The new validation/derivation uses a cached layer/page index, with 100,000 document layers and 256 ancestor levels as explicit supported bounds. Complete derived frame/body/header positions must be finite, and dimensions must be finite and within the document’s 1,000,000-unit size limit before creation or generic move/resize can publish. An empty optional record list performs no new hierarchy scan or size check. It does not expand the rest of the editor’s independent document/rendering limits.

Internal duplicate/copy, validated cross-document clipboard payloads and page duplication remap all owned layer/record IDs. Selecting an owned body/header for copy includes the complete logical card. A self-contained code-card clipboard payload declares its Whiteboard workspace. Pasting into Design or Slides produces ordinary editable frame/text artwork and an explicit demotion notice; no code-block controller survives. This includes active-slide containment. Pasting into another Whiteboard retains validated logical records. Moving a logical card between pages retains its identity and literal code; page deletion cleans its records. UI Delete/Cut of any owned child removes the complete card, matching copy closure; all owned/inherited locks and every actual descendant of an expanded card are checked before deletion and native Cut preflight. A failed clipboard write does not cut. Sticky/table deletion behavior is unchanged. If an owned layer is explicitly removed through the generic document API, the record dissolves and surviving artwork remains ordinary editable layers. This does not silently recreate deleted code. Existing source MCP node/page operations preserve and validate this metadata, including malformed/oversized text rollback and Undo; no new tool or capability is added.

SVG/raster export and the canvas use the same ordinary frame/text artwork. The Figma Bridge validates the new metadata before creating anything, then explicitly reports that code-block language/ownership metadata is omitted; its literal code transfers as ordinary editable text. Bridge mock tests do not establish a real Figma desktop round trip. Reusable component-library publication starts from a fresh reusable graph and excludes unrelated code cards and Whiteboard records. Imported library packages containing this new logical editing metadata refuse explicitly. Authorized document/MCP reads contain the saved code as ordinary file text; asset omission is not source-code redaction.

The panel permanently invalidates retained callbacks after document/page/selection/mode/modal/Motion/panel changes, including away-and-back cycles. Draft generations prevent an old Apply callback from using a previous same-event source value. Writes require the Design mode in a visible local Whiteboard outside Motion, and respect owned/inherited locks and managed-instance restrictions. Opening the Code panel cancels an unfinished Whiteboard drawing. At 125% interface scale in a 720-pixel-high window, its own panel scrolls and the controls remain keyboard reachable.

Source tests cover raw whitespace and special characters, both document versions, controller conflicts, style preservation, the aggregate/per-body limits, malformed metadata, cached lookup, normal generic text edits, page/copy/remap/delete lifecycle, Bridge preflight and source MCP atomic edits/Undo. Browser coverage exercises real creation and centering, shared SVG raster pixels, save/download/reopen, literal clipboard fallback, independent copies, transformed ancestors, live canvas resize, locked controls, retained source/draft callbacks and short-window keyboard reachability. Native clipboard and real Figma reference verification remain separate pending checks. No build, download archive, package, native resource, website or release metadata was regenerated.
