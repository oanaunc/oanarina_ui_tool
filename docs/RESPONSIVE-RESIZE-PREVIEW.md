# Responsive frame resize preview

**UI-23-030 — Responsive resize preview: implemented as a local single-frame workflow.** Select a Design frame, expand Responsive resize preview, enter dimensions or choose a preset, and choose Preview resize. Before/after images show the actual supported static renderer after shared constraints, auto layout, grid tracks, responsive guide bindings, component materialization and text metrics run on a cloned document. Preview does not edit saved artwork, selection or Undo history. Explicit Apply commits the previewed result in one transaction with normal Undo/Redo and `.oui` save/reopen.

The requested dimensions resolve through existing hard minimum/maximum limits. A locked aspect ratio makes width drive both dimensions, including presets; the resolved dimensions and any clamping are shown. Apply sets the frame's width/height policies to fixed and retains child sizing policies. A free-layout frame, auto-layout frame or a frame currently hugging contents can use this workflow. A selected frame controlled by its parent's flow layout, its own guide bindings, or width/height variable bindings must first become independently resizable through the existing controls. No binding or constraint is silently detached.

Both previews use the selected frame's local viewport, preserving supported ancestor transforms, clips and masks. Reveal outside frame expands each image to conservative painted bounds and disables only the selected frame's clipping in that image. Nested clipping and supported masks remain. A dashed border marks the frame bounds. SVG images are isolated from the document DOM, so their clip/mask/paint/effect IDs cannot collide with the live Canvas. Rendering uses the shared export renderer and its font embedding. Images are static, including saved video posters; hyperlinks, prototype interactions and video playback do not run.

A bounded changed-box list shows model X/Y and dimensions before and after, plus counts of changes propagated to other source-linked layer boxes and removed generated layers. These are saved box values; transformed ancestors can also move painted content without changing a child's own box values. No raw validation signatures or private reference IDs enter user reports.

## Apply origin and ownership

A preview belongs to the exact originating document object, page, frame selection, editor mode, Motion state/time, modal/home/hidden-UI state and font revision. Changes invalidate both drafts and cached previews, including a native Motion transition away and back in the same event sequence. Font revisions invalidate the preview even when a fixed text box's dimensions stay the same. Motion must be closed; this workflow previews saved base Design artwork, not sampled timeline poses.

Locked frames and ancestors permit read-only preview, but Apply refuses until unlocked. Managed instance frames, generated slide/sticky/table frames and other workspaces use their source/workspace controls instead. A selected mask/boolean source or a frame owned by a live boolean or mask-source ancestor refuses preview: isolating only that operand would omit the affected result/stack. Imported slice ancestors and clipped nonrectangular ancestor shapes also refuse because their required ghost clip cannot be faithfully represented by this isolated renderer path. Ordinary external sibling masks and rounded rectangular clips remain supported.

The headless helper fingerprints project layer geometry, parent/type, transforms, layout direction and sizing policies before and after derivation. It detects stale geometry before mutation and validates every final derived project box/policy snapshot before committing. Paint and textual content are not part of that geometry token; the UI's exact document-object and font-revision checks provide the additional origin guarantee. Apply validates resolved frame dimensions and the final shared derivation. A source, text or layout controller producing a different result refuses the whole transaction; there is no partial resize or Undo entry.

No schema field, migration, document version, MCP operation or native permission was added. Headless tests use the same document/layout primitives; source MCP continues to use its existing shared derivation and explicit node-update operations.

## Bounds and conservative overflow

Analysis accepts up to 20,000 project layers and a conservative 16 MB complete-project JSON payload estimate, including unrelated embedded assets and fonts. Payload traversal stops at 2,000,000 values or 64 metadata nesting levels before cloning/serialization; JSON escapes and UTF-8 characters count toward the estimate. Assets are never omitted to fit the budget. Geometry signatures have a 4 MB limit. Required frame/mask/clip rendering context is limited to 500 layers and 64 ancestors before expensive render work. Each SVG image is limited to 4 MB and at most 560 × 320 intrinsic pixels. Oversized projects or scenes give an explicit refusal.

The shared solver must produce a stable geometry snapshot on an additional text/layout pass. Layouts that do not stabilize within its existing iteration budget refuse rather than presenting an unreliable size. Positive finite requested dimensions are limited to 1–1,000,000 px, and derived positions must stay within the document coordinate range. Collapsed/nonfinite ancestor transforms and unsupported isolated ownership contexts refuse explicitly.

Its supported ancestor/mask context and live Motion sampling remain. Conservative painted rectangular bounds include stroke/effect padding, while masks, nested clips and occlusion can conceal listed candidates. This pass does not provide exact pixel-overflow proof. Existing candidate reveal/selection remains view-only and checks its live origin before navigation.

## Validation and limits

Core checks cover every existing constraint mode, row fill/min/max, grid spans, durable guide bindings, aspect limits, hug-to-fixed sizing, auto-height text, transformed ancestors, locked read-only previews, component propagation outside the frame, one Undo/Redo/save, stale origins, final position/dimension refusal, ownership/workspace/source guards, malformed dimensions, coordinate overflow, subtree/project/depth limits, preclone payload refusal, UTF-8/escape estimates and isolated mask rendering.

Actual browser checks inspect rendered before/after pixels, grid/guide dimensions, Canvas transforms, nested-mask overflow pixels, unchanged Canvas SVG definitions, hard limits/aspect and preset controls, lock/source refusals, invalid sizes, native mode/selection and font-revision invalidation, transformed/scaled/reflected ancestor pixels, actual auto-text line counts and ancestor ownership refusal. The existing overflow pixel check decodes the real isolated SVG image; it is not replaced with a markup-only assertion.

Arbitrary multi-frame breakpoint canvases, automatic browser/device emulation, live interactive/video playback, exact occlusion proofs and unsupported source-controlled frames are outside this workflow. No complete Figma behavior/reference verification is claimed. No build, bundle, native app package, archive, version, website, feature-register generation or push is included under the user's build freeze.
