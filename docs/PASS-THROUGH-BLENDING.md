# Explicit pass-through blending (partial)

The Layer inspector offers **Pass through · non-isolated** for groups, frames and sections. Choosing it atomically saves `blendMode: 'pass-through'` and `isolate: false`; descendants blend against the actual enclosing artwork. The existing isolation checkbox remains available for ordinary blend modes, and is disabled while explicit pass-through owns the non-isolated setting. Choose **normal** to leave this constrained mode before enabling isolation, opacity, clipping, fills or effects. Unsupported mixed selections refuse as one transaction.

This does not introduce a new compositor for legacy groups. Existing absent/normal modes were already non-isolated unless the author enabled isolation or another SVG operation isolated them. Their metadata and rendering branches remain unchanged. Explicit pass-through adds a reachable, saved, validated guarantee and guarded controls around that existing SVG capability. Shared Artwork maps the explicit value to `mix-blend-mode: normal; isolation: auto`; no invalid CSS `pass-through` value is emitted. Ordinary isolated groups still use `isolation: isolate`.

Supported explicit containers are independent, unpainted groups/frames/sections at exactly 100% own opacity, isolation false, no own clipping, masks, effects, media, Boolean controller or ghost/export ownership. Affected pages cannot contain sibling masks or Motion keyframes. Component/instance ownership and ancestry refuse. The hierarchy supports 64 levels, affected pages 20,000 layers, and affected files 100,000 layers. These are conservative authoring restrictions, not claims that SVG cannot render broader cases. An ordinary enclosing ancestor may itself be isolated or translucent; the explicit container passes through to that ancestor's actual local backdrop. Real browser pixels test the nested isolated/half-opacity case with transformed descendants.

Default .oui data is not normalized on open. Versions 1 and 2 preserve the additive blend value; malformed/conflicting imported states refuse before replacement. Source edits validate before derivation and again at the final metadata boundary; Canvas drafts validate before publication. UI source receipts permanently invalidate retained callbacks across document/page/selection/mode/modal/Motion/hidden changes, while fresh controls recover after an equal-value cycle. No-op fields preserve bindings/history; changes, recovery, Undo, Redo, save and reopening use ordinary transactions. Existing component/clipboard validation applies; an unsupported component-owned conversion refuses instead of silently dropping the mode.

The shared Canvas, editor SVG/PNG/JPEG and source-MCP full-page SVG preserve this compositing. Culling retains the complete scene on explicit pass-through pages. Source-owned selection/profile exports that include the container or any descendant require the complete original page; dropping the enclosing/preceding backdrop or substituting ghosts refuses. Isolated layer thumbnails on an affected page and component previews requiring a pass-through ancestor show a local diagnostic before returning SVG nodes, rather than rendering against the wrong backdrop or crashing the editor. Direct `exportSvg(nodes)` treats the supplied nodes as an entire authored scene; context-owning entry points validate their source before calling it. No editor grid/page CSS or other application backdrop is promised in exported artwork.

Motion keyframes, animated export, prototype/Smart animate/scroll presentation and component-owned explicit containers remain unsupported. Reduced own group opacity is deliberately refused: `isolation:auto` does not override opacity/filter/mask isolation, and this workflow does not claim Figma's general pass-through group-opacity behavior.

Standalone Figma Bridge validates the supported outgoing subset before creating native pages and writes the native `PASS_THROUGH` enum for that subset. API mock tests verify the actual property assignment and atomic refusal, not a desktop round trip. Native Figma pass-through export into Forma retains the prior legacy normal/non-isolated reduction with a new explicit report; the importer does not silently claim reduced-opacity/native backdrop parity. REST JSON import keeps its existing counted pass-through reduction. SVG keeps supported appearance, not a native plugin-reference guarantee.

Validation uses pure/core tests, actual Chromium Canvas/editor/headless SVG pixels (cyan isolated child versus black multiply over a red backdrop), transformed nested backdrop/isolation/opacity, later painter order, reachable controls, source ABA/recovery, mixed atomic refusal, no-op bindings, keyboard ownership, import/save/reopen, Undo, source-MCP persistence and standalone Bridge preflight. Mac WKWebView and live Figma acceptance remain unverified. No native build or release artifact was produced.

The [official Figma BlendMode API](https://developers.figma.com/docs/plugins/api/BlendMode/) defines the outgoing `PASS_THROUGH` enum; it does not establish native round-trip acceptance.

Reference: [W3C Compositing and Blending Level 1](https://www.w3.org/TR/compositing-1/), especially SVG non-isolated groups, isolation triggers and group invariance. Two-dimensional transforms alone do not create isolation; opacity, filters, masks and non-normal group blending can.

Status recommendation: **UI19-018 partial**. The explicit bounded workflow works; general Figma pass-through opacity/effects/masks/components/animation and real reference verification remain outstanding.
