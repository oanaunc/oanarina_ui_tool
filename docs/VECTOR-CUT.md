# Vector cut: segment scissors

In point editing, the vector inspector includes **Cut path · scissors**. **Cut path** enables a canvas overlay: choose a position inside one existing segment and release to cut. A marker shows the candidate and snaps to an anchor within 8 screen pixels, which cuts there: the anchor is duplicated and each side keeps one of its handles. Moving too far from the segment, or choosing an anchor that already ends an open path, refuses the cut. The segment picker uses readable contour/segment names, and the active canvas hint has a theme-backed badge. A separate **Cut chosen segment** control accepts a segment and cubic parameter percentage, providing an accessible deterministic alternative. This percentage is the curve parameter, not percentage of arc length.

An open contour becomes two open contours in the same layer. A closed contour opens at duplicated coincident cut endpoints, retaining all original edges in rotated order. Cubics use exact de Casteljau subdivision; straight edges remain straight. No flattening, normalization, layer rebasing, new coordinate basis or style materialization occurs. The original node ID, parent, dimensions, path basis, rotation/reflection/scale, paint/stroke settings and other metadata remain unchanged. Only contours and the editor’s selected endpoint keys change. Newly exposed caps can change appearance according to the existing stroke style; this is an intentional consequence of cutting.

Cuts use one ordinary Undo transaction and survive save/reopen, `.oui` versions 1/2 and existing validated MCP contour updates. Tool/candidate state never appears in saved documents or exports. Mathematical sample checks cover both subdivided halves and closing segments; browser export checks allow ordinary antialias variation from equivalent cubic command subdivisions while requiring the same curve coverage.

## Partial scope and safeguards

This is a scissors workflow on segments and anchors. The filled-shape [Knife](VECTOR-SEPARATION.md#knife) is a separate tool. This tool does not implement automatic cuts at all intersections, general vector networks, multi-layer cuts, separate output layers or cut-and-delete gaps. The existing Split at points operation remains available for selected anchors.

Supported input is a contour path with at most 32 contours and enough room for two new anchors within 512 total result anchors. Each contour needs at least two anchors. Coordinates, absolute control points and visible canvas controls must be finite and within ±1,000,000; the path needs a finite nonzero coordinate box and an invertible ancestor transform. A single cached path-to-world matrix and node-map ancestor lookup are reused for all controls and pointer hits, keeping tool preflight/render geometry work linear in page size plus controls. Pointer picking occurs against the visible world-space cubic, including nonuniform scale/reflection; the committed parameter subdivides the original local cubic exactly. Parameters within 0.00001 of either end, near-zero pieces and near-zero picked segments are refused.

Visible fills, non-centered or dashed visible strokes, non-solid visible stroke paints, arrowheads, visible effects, masks on the edited node, live boolean results/ancestors, children on the path, automatic layout on the path and managed instance layers are excluded. At least one visible positive-width solid centered stroke is required. Hidden paints are retained but are not converted. Filled-region knife behavior remains unimplemented. The tool operates in the ordinary Design workspace, with one effectively visible unlocked path selected in point editing, outside Motion and modal/hidden interfaces. At most 64 ancestors are supported.

A preflight runs before editor mutation, and a post-derivation validator refuses a component/layout controller that overwrites the requested contour or changes the saved target fields. Main component source edits can propagate through the existing component pipeline; managed generated instances must be edited at their source or detached first. Existing animation tracks retain the same coordinate basis; topology cannot be cut while Motion is open.

Escape cancels a pending cut and exits Cut while retaining point editing. Blur, document hiding, resize, changed document/page/selection/mode/camera, UI-scale changes and source edits cancel captured cuts. Pointer cancel/lost capture cancels the pending operation. Cut and Bend/mask inspection/image crop/gradient handle modes exclude one another. Retained same-event handlers verify the active context identity and its invalidation proof before starting capture or hover; a context changed away and back cannot revive a pending cut. Middle mouse or Space can pan; the resulting camera change disarms Cut. Blank canvas clicks do not silently edit a path while Cut is active. After a successful cut the mode re-arms only if the remaining geometry still satisfies the tool budget.

## Verification

Core cases cover exact cubic halves, straight/closing/compound topology, unused and neighboring handles, source immutability, affine world picking, endpoint/zero/limit/style refusal, all non-contour fields, Undo/Redo/version parsing, stale and revived contexts and mode exclusion. Browser cases cover actual pointer and numeric cuts, Undo/save/reopening, rendered curve coverage, 125% UI with transformed ancestors, interruptions, retained handlers, near-anchor refusal and explicit unsupported-fill feedback. Source MCP checks use the existing contour schema to persist exact results, reject malformed geometry atomically and Undo the change. No new model schema, native IPC or MCP operation is added.
