# Editing several contour paths together

Select two or more existing contour-path layers, then choose **Edit selected vectors together** in the inspector. The canvas displays all their anchors at once. Click an anchor to select it, Shift-click to add/remove it, or drag a box over anchors across the paths. Shift-box adds; Option-box subtracts. **Select all vector anchors** and Command-A select anchors without changing the selected layers.

Drag selected anchors to move them by the same **canvas-space delta**, independently mapped through each path's coordinate basis and signed affine ancestry. Selected anchor tangent handles remain editable: mirrored/aligned behavior follows the existing point mode; Option adjusts the grabbed handle independently. Control-drag integrates new movement at one tenth speed, preserving earlier travel when the modifier changes. Arrows nudge selected anchors one canvas unit, or ten with Shift. Delete removes selected points across the paths as one atomic operation; a contour reduced below two anchors disappears, but removing all usable contours of any path is refused before any path changes.

Actual artwork and point overlays preview pending geometry. Saved nodes remain unchanged until release. One release, nudge or deletion creates one ordinary Undo transaction; all affected IDs, styles, parent relationships, dimensions, path bases and affine poses remain intact. Save/reopen and both `.oui` versions retain the contours. A click without movement creates no history. Escape, Enter or **Finish editing vectors** exits this editor-only mode; the session and its qualified point selection are not saved.

This is **partial UI-16-023**: real simultaneous anchor/tangent editing, box selection, nudging and point deletion across existing contour paths. It does not implement shared networks between separate layers, cross-layer joins/topology tools, new contour drawing, anchor-fragment clipboard/Cut, arbitrary shape conversion or a shared coordinate basis. Command-X is refused explicitly while this mode is active; finish point editing to cut layers through the ordinary clipboard. Other supported layer actions retain their normal behavior and source mutations end the session. This is not a claim of full Figma parity or reference verification.

## Limits and safeguards

Supported input is 2–16 independent contour paths with IDs of at most 512 UTF-16 code units, at most 4,096 anchors total, on a page of at most 20,000 layers. Convert other shapes to contour points individually first. Each contour needs at least two anchors and a nonzero coordinate basis. Paths cannot have children, live booleans or their own automatic layout. All target paths and ancestors must be effectively visible, unlocked and outside managed instances/live boolean hierarchies. Motion must be closed, the Design canvas visible, single-path editing closed, and Move/Scale active. Up to 64 ancestors are supported. Coordinates and absolute controls, before and after mapping, must remain within ±1,000,000. Node maps and one matrix/inverse per path keep preflight and point updates bounded; no page scan occurs for each anchor.

The complete selection, source document/page, tool, camera, UI scale and editing mode belong to a captured session. Any source mutation, external layer selection, mode/camera/UI-scale change, modal, Motion opening, lock/ownership change, blur, hiding or resize ends the session and discards its draft. A context changed away and back cannot revive a captured gesture. A second or nonprimary pointer cannot replace it; unrelated pointer cancellation is ignored. Space during a drag cancels its draft before navigation. Space/middle mouse can subsequently pan, and camera movement ends the session.

Point changes preflight the live hierarchy again, validate all planned geometry before mutation, then verify the complete affected and unaffected target nodes after layout/component derivation. A controller that overwrites the request makes the whole transaction fail. Inputs and plans do not become mutable aliases of saved contours. Single-vector Cut, Bend, eraser, lasso, image crop, gradient handles and mask inspection exclude this mode. Activation synchronously cancels older Canvas gestures, including same-event activation/reset.

## Validation

Core checks cover qualified IDs, signed/nonuniform ancestry and path bases, equal canvas movement, tangent constraints, exact field preservation, Undo/Redo, `.oui` versions, plan cloning, deletion/malformed/overflow refusal, stale sessions and ownership/budget guards. The 20,000-layer / 64-ancestor / 4,096-anchor case verifies no `nodes.find` scans during mapping and movement planning. Browser checks use real selection, preview/drag, cross-path box selection, keyboard nudges/deletion, fine Control movement, 125% UI transforms, Undo/save/reopen, interruptions, stale/nonprimary pointers and explicit unsupported actions. Existing MCP multi-operation contour updates remain the interoperability path; no document schema, native IPC or new MCP operation is added.

## Snapping

With vector geometry snapping on, the grabbed anchor snaps to anchors and curves outside the moving contours, and every other selected anchor keeps the same canvas delta. Control and Command skip it, as in single-path editing. Handles do not snap.
