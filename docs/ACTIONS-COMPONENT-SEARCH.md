# Component search in Actions

Actions → Components searches the existing definitions in this file and its enabled installed local libraries. Search matches every normalized query word across component/set name, exact variant name, asset-group tags, source page and library name. The library filter separates this file from installed sources. Every real indexed variant has its own result; Enter or clicking inserts that exact variant as a linked instance at the current page root and visible canvas center, in one Undo transaction. Go to selected component source navigates read-only to the actual main across pages.

Disabled/missing library groups remain available to their existing consumers but are excluded from new search insertion. Availability is checked for both the set/group and its exact mapped main: independently authored variant sets cannot relabel a disabled or missing installed main as a local component. Missing set status uses its bounded saved definition baseline to identify member mains even through local aliases. If that ownership cannot be verified, the library is excluded with an explicit diagnostic. Enabled aliased mains retain their original library label. Installed-group and current-file publication deprecation advice remains visible beside matching results and their aliases; it is advisory and does not prevent deliberate insertion. When an old advisory baseline cannot establish exact alias membership, a library notice reports that uncertainty instead of assigning a reason by name. Display names are never used as identity.

The source catalog bounds indexing to 100,000 visited layers, 20,000 results, 10,000 variant references and 20,000 tag references, with a 40-million UTF-16 search-text budget. Library metadata supports eight dependencies and 30,000 inspected node/set mappings; missing/deprecated-group baselines have a 12-million-character parse budget, and current-file advisory membership walks allow 10,000 variant references. Queries are limited to 300 UTF-16 units. Only 50 results render at a time, with Previous/Next and keyboard movement within that page. Reaching an index budget is visible, rather than claiming a complete search. No arbitrary baseline, image/font bytes or document text is returned in results.

Local query/library/page changes synchronously invalidate retained result handlers. Editor-context departures invalidate a permanent proof; a fresh rendered control gets a new proof and can retry. Switching Commands/Components also invalidates old mode controls before React commits. Source checks precede insertion and the existing component/store pipeline validates the unpublished candidate. Slides, hidden/home/Inspect views and open Motion refuse insertion/navigation with guidance. Existing source locks are respected as reusable definitions without editing them.

Commands retains ordinary keyword/category/recent-action behavior. Its search field still receives initial focus; the new Commands/Components controls join the existing dialog focus cycle. Native text selection, Escape dismissal, shortcut labels and standard command routing remain covered by browser checks.

UI-42-005 remains **partial**, with reference verification pending. This does not search uninstalled cached snapshots, online/organization libraries, Figma Community, plugins or widgets. No new command ID, `.oui` schema, native menu/IPC permission, network service, font redistribution or external account is added.

## Validation

Core tests cover real snapshot installation/remapping, exact variants, tags/library filters, disabled/missing groups, valid independently authored mixed-set aliases, stale insertion refusal, multiple libraries, bounded indexing, `.oui` one/two and one-step Undo. Real browser checks cover insertion and exported/reopened `.oui` files, source navigation, filter/pager/keyboard behavior, stale query/mode/editor callbacks and fresh recovery, availability bypass refusals, and 125% short-window containment. Combined validation is recorded in the checkpoint report. No native/package/build, archive refresh, release bump or website deployment is created.
