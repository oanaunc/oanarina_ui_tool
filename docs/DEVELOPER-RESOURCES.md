# Developer resource links

Select a layer and open **Inspect**. The Developer resources section attaches named issue, documentation, repository or other HTTP(S) links. Edit name/kind/URL, remove a link, open it explicitly or copy its displayed URL. Attach/edit/remove each use one normal document Undo step; ordinary save/reopen, clipboard/page copies and shared component defaults/explicit instance overrides preserve the metadata. The inspection report includes the named resources and URL details.

This is file-local link management. It does not fetch sites, embed remote content, synchronize issue status, authenticate accounts, publish documentation, discover a repository or run a code-generation plugin. Resource sites keep their own permissions. Opening a link uses an explicit user click with an isolated opener; there is no automatic navigation or request.

Optional `devResources` arrays use existing `.oui` versions one/two without changing legacy documents. A layer supports 32 resources and a document 4,096; IDs/names are bounded to 200 characters and URLs 4,096. Shared import/store/MCP validation rejects unsupported fields/kinds, duplicate per-layer IDs, disallowed controls, executable/file/data/protocol-relative URLs and embedded URL credentials. Explicit edits normalize URL syntax through the platform URL parser. Resources have no filesystem or native IPC privileges.

Mutation requires the original inspected document/page/selection/mode context, an unlocked target and Motion closed. Source/context cycles permanently invalidate retained handlers and drafts; no draft text is carried to a new source target. Locked layers remain readable and copyable. Component source changes update inherited lists; explicit instance lists remain overrides and can be reset through existing component controls. Resource IDs are local list identities, not graph references, so literal URLs remain unchanged in page/clipboard remapping. Normal library definition edits remain real conflicts.

The editable Figma Bridge reports omission of resource links, retains existing component links when only resource metadata is overridden, and never prints resource URLs in its report. Its portable preflight intentionally accepts a narrower authority subset than the app URL parser: ordinary ASCII hosts, canonical dotted-decimal IPv4 and hexadecimal IPv6 with valid numeric ports. Encoded/punycode hosts, mixed or noncanonical address forms must keep their links in Forma or remove the metadata before editable transfer. This is not a full Figma Dev Resources API implementation or a real desktop round-trip claim. The original `.oui` keeps all supported app URLs; SVG/raster export does not embed developer resources.

Source checks cover strict schema/URL/count bounds, legacy preservation, atomic malformed imports, real store Undo/Redo, linked defaults/overrides/reset, clipboard/page/report semantics, source MCP atomic edits/Undo and Bridge omission/preflight/link preservation. Actual browser checks exercise attach/edit/remove/copy, executable-URL refusal and malformed File Open, stale same-event handlers, locks, genuine save/reopen, compact 125% UI and absence of background resource requests. Native/WKWebView and real Figma reference verification remain pending. No package, archive, installer, native build or website change is part of this source workflow.

Isolated source acceptance passes 1,802 core tests across 151 files, 14 affected browser checks (five new resource workflows), 67 source MCP checks and both editor/MCP TypeScript checks. Independent review cleared URL-authority/Unicode-whitespace checks, source proof, locks and truthful Bridge omission. These are pre-integration counts; combined acceptance is recorded separately when merged.
