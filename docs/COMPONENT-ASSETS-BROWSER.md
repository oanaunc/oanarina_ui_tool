# Local component assets and naming folders

The Assets tab now contains a local component browser across the current document's pages. It keeps ordinary main components separate from variant sets: a set appears once and exposes verified local variant choices. Source page/name context stays visible, and there is no remote library or cloud account dependency.

## Implemented local behaviors

- **UI-27-005 — Component naming paths:** slash-separated segments form exact virtual folders. A guarded naming-path editor normalizes 1–32 nonempty segments (up to 1000 characters). Renaming a set updates its set name and container together without changing variant property values. Existing legacy names remain readable; names beyond the browsing limit appear at root with a notice.
- **UI-27-012 — Component Assets panel:** text search matches indexed names, page names and tags. Tag and source-page filters combine with folder scope. Set cards have variant choices and show the chosen variant's actual source context. Preview is explicit and limited to one card at a time. Insert creates a linked instance at the current page root, centered in the actual visible Design canvas; it does not insert into a selected locked parent or managed instance. Go to source navigates across pages, clears layer filters/search and selects the verified local main.
- **UI-27-036 — Organization by folder:** a real segment navigator provides All components, root names, immediate subfolders, counts and breadcrumbs. Without search, a folder shows its direct assets; a query searches its descendants. `Buttons` never matches the sibling `ButtonsExtra`. Move to displayed folder updates the asset's naming path without moving its canvas parent. Empty folders are not stored independently of names, and bulk folder rename/drag moves are not provided.

Each mutation uses the shared document transaction and one Undo step. Naming paths save and reopen as existing `.oui` names; no new model field or migration is needed. Pure helpers keep the same model usable in headless code. Existing MCP update/name operations and schema remain unchanged.

## Safety and limits

Insertion, source navigation and path changes require the live Design context, with Motion closed and no modal/home/hidden-UI transition. Naming drafts capture their originating document/page/selection/mode and expire on context changes, including native commands. Naming mutations honor inherited source locks and reject managed generated mains. Set renames check the container and all members; sets with more than 1000 variant references refuse this mutation rather than performing unbounded validation. Locked library sources can still be previewed/navigated or instantiated without editing the source; an instance retains its source's ordinary inherited lock metadata.

The catalog processes at most 100,000 layers, 10,000 variant references total (1000 per set), and 20,000 tag values. It stores at most 20,000 assets and 100 tags per asset; the tag menu shows 200 choices. Duplicate variant references are deduplicated during bounded iteration. Only verified indexed members become variant choices. If the declared default is not verified within the budget, a notice identifies the first verified local member being shown. When indexing is incomplete, the UI warns that additional definitions/tags can be omitted and unindexed set members can also appear as main cards. These limits do not reject or rewrite valid legacy document metadata. A set's page filter uses its indexed default/fallback source page; choosing another variant shows that variant's actual page.

Cards paginate by 24, folder buttons by 50, and variant options by 100. A selected option always remains present, a default beyond the first page is aligned correctly, and pages clamp when lists shrink or Undo restores them. Previews stop before renderer/export work if a component exceeds 256 layers or 64 ancestors. Large components remain insertable and navigable. Previews use saved base artwork, including static video posters; surrounding artwork and external sibling masks are excluded and the UI says so. No Figma screenshots, user files or remote resources are published by this workflow.

The preserved Assets create-from-selection entry checks locked/managed hierarchies, current context and workspace before invoking the existing creation command. **UI-27-001/002/003/004 remain partial**: main creation, frame/group conversion and existing main-component icons have real basic paths, but this work does not establish complete creation semantics or fix every global shortcut/command path. It adds no cloud library, team publishing or native Figma reference-verification claim.

## Validation

Core tests cover exact path segments, canonical names, malformed paths, cross-page indexing, set choices, filtering, inherited locks, atomic set/container names, insertion, saved compatibility, Undo/Redo, source immutability, preview limits, guarded creation and duplicate-heavy legacy indexing budgets. Browser tests exercise real folder/tag/page controls, chosen-variant previews/insertion, source navigation, path rename/save/reopen/Undo, move to an ancestor folder, context cancellation, Motion refusal, list pagination, source locks, actual 150% canvas-center coordinates, default variant 150 and list shrink/Undo behavior. Existing frame preset/workflow checks also pass through the preserved Assets path.

No build, bundle, download archive, native package, version, website or feature-register generation is part of this source change. Exact Figma reference verification remains pending.
