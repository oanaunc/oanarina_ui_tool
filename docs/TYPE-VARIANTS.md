# Character variants implementation

Implemented source workflows for UI-22-008 (Small caps), UI-22-009 (Superscript), and UI-22-010 (Subscript). These are usable Forma behaviors; reference verification against Figma remains pending. UI-22-055 line-height unit conversion is outside this change.

Character formatting contains whole-layer Capital forms and Position selectors, including mixed selections, plus matching selectors for a selected character range. Returning a range to Normal explicitly overrides an active base variant; Clear selected range formatting returns to inheritance. Locked ancestors, Motion, stale document/page/selection and modal/home context prevent new formatting mutations. The existing shared history handles Undo/Redo, and `.oui` saves retain both base and range values without changing the document version.

`smallCaps` and `textPosition` are optional additive fields in the node and range text styles, local text styles, component overrides, and bounded MCP node edits. Imported invalid values fail validation before document mutation. Existing normal-text outline signatures remain compatible; active variants invalidate preserved outlines so the live renderer takes over.

The canvas and SVG export use the same styled text spans and line layout. Small caps use CSS `font-variant-caps: small-caps`, allowing actual font forms where supported and browser synthesis otherwise, without altering source characters. Browser measurement uses a hidden span with the same caps/axes/features. Font subset requests include uppercase fallback glyphs. Headless text measurement has no browser shaping engine and retains the existing approximate advance model; small-cap widths in headless MCP layout are approximate. Exact font-dependent Figma matching is not claimed.

Superscript and subscript preserve nominal font size and source characters. Both render at 65% of nominal size, with baseline offsets of −0.5em and +0.25em respectively. Wrapping uses the scaled advances. Line envelopes reserve the raised ascent and lowered descent, including measured browser glyph extents when larger than the nominal envelope; auto height, ellipsis visibility, line advance, and vertical alignment consume these envelopes. Headless fallback reserves 20% of the positioned size for descent. These are deterministic typographic positions, not a claim to match each font's OpenType superior/inferior glyph substitutions or Figma's metrics. Arbitrary font-axis effects on vertical glyph extents remain subject to the existing canvas measurement limitations.

Custom rich-text clipboard JSON preserves the fields exactly. HTML copy uses `font-variant-caps` and semantic `sup`/`sub` elements; HTML-only paste restores nominal sizes and positions. External applications may use their own superior/inferior offsets. Editable Figma Bridge import explicitly reports that character variants are omitted, while SVG export preserves their rendered appearance. No real Figma desktop round trip is claimed by mock checks.

Validation: 947 core tests across 87 files, editor and MCP TypeScript checks, and the source-only MCP transaction case passed. All 11 relevant browser interactions passed; the SVG rasterization case also passed with a deep combining-descender assertion after the glyph-metric safeguard. Seven new core cases cover validation/atomic refusal, range clipboard/save, envelopes/advances, SVG output, legacy outlines, style/component propagation and Bridge omissions. Four new browser cases cover real selectors and Undo/reopening a saved document, HTML-only clipboard, actual SVG glyph rasterization, and inherited-lock/Motion refusal. The seven existing rich-text browser interactions also passed. A new source-only MCP transaction case covers persistence, invalid batch refusal and Undo. No package, installer, native build, archive, release version, or website files were generated by this work.
