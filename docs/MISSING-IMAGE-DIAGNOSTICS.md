# Missing embedded-image diagnostics

The Design/Inspect canvas now shows selectable **Missing image**, **Invalid image** and **Broken image** markers for supported image layers, image fills/strokes, empty texture sources and video posters. Validated procedural pattern/noise sources are excluded: their tiles are generated from source parameters, not missing external files. Selecting the marker selects its actual layer without changing the document or starting a move gesture. Locked and managed layers can be inspected this way; their normal editing permissions remain in force. The selected-layer inspector explains the failure and points to the existing Choose/Replace image/texture controls. For a legacy empty image layer with a solid fill, first change its Fill type to Image, then choose an image.

The classifier distinguishes absent source data, invalid/oversized data metadata, unconfirmed decoding, and an actual browser decode failure. A syntactically valid source is never called broken merely because it has not loaded. Existing native SVG `<image>` load/error events supply decode results; there are no separate `Image` probes, fetches, remote-URL requests or asset-cache writes. PNG/JPEG/WebP/GIF headers are checked; SVG data is left to the existing browser image decoder. This does not promise comprehensive binary repair, intrinsic pixel-dimension inspection of imported legacy bytes or browser codec parity. Video playback already supplies its own saved-poster/codec message; this pass checks its embedded poster, not video decoding.

Markers are editor overlays **outside** the authored Artwork, alpha/luminance/vector masks, filters and clipping stacks. They include an authored-layout-box outline and a constant CSS-size label. The label uses the authored box's fully transformed upper-left point; the outline follows signed/nonuniform ancestor affine transforms. These are source-location diagnostics, not tight ink bounds or assertions that the affected pixels are currently visible through occlusion, masks or ancestor clipping. A broken mask source may therefore have a visible diagnostic even while it masks all target pixels away. Hidden/zero-opacity ancestry and children of a live Boolean result are suppressed. Draft gestures, Motion, prototype editing, vector editing, active crop/gradient and hidden UI suppress the overlay; sampled Motion scenes do not publish diagnostic conclusions.

Authored image source bytes, fills, opacity, stacking, masks and exports are unchanged. Invalid live image hrefs are suppressed only inside this editor diagnostic scope. Standalone Artwork, previews outside the canvas and SVG/PNG/PDF exports keep the original rendering/source behavior and contain no diagnostic labels. A valid replacement uses the existing image-import validation, creates one normal Undo step and clears the marker after decoding; Undo restores the old source and marker. Save/reopen keeps original authored data, with no status metadata added to `.oui` one/two.

Each immutable authored page gets a bounded index: at most 20,000 layers, 256 absolute ancestor levels, 50,000 paint entries, 512 image sources and 64 MB of unique source-text scanning. Each inspected embedded image is capped at 20 MB. The raster signature check decodes only a short prefix. Native image decoding still uses the browser's existing decoder and its own resource/codec limits. Exceeding a diagnostic budget produces a visible paused message with inspector details, rather than asserting that assets are missing. No page/object is removed or normalized. The scan uses maps and cached ancestry; it does not run against every pointer-preview scene.

Decode callbacks belong to an exact document/page/source scene and editor mode. A source or context cycle permanently invalidates the old session, including same-event away-and-back changes. Scene publication and decoded outcomes are volatile and local to the current Canvas instance; other cached files do not acquire statuses or register assets. Selection-only changes do not trigger another page scan or remount native images. The marker's separate full-context proof rejects old retained selection callbacks.

## Source validation

Pure tests cover absence/malformed/header classification, unconfirmed decoding, mixed paint/stroke/texture ownership, `.oui` preservation, signed/nonuniform ancestry, visibility, absolute hierarchy limits, source limits, collision-safe keys and export/mask isolation. Actual Chromium tests exercise real valid and truncated PNG decoding, selectable messages, replacement/Undo/save, hidden and transparent ancestors, real mask ownership and exported pixel preservation (without prescribing browser behavior for corrupt mask-image bytes), Motion suppression, retained native/marker callbacks and readonly transformed empty images. Browser tests use synthetic public fixtures only.

UI-53-026 remains partial: this is a bounded image/poster diagnostic workflow, not a general missing font/video/component/library/resource placeholder system. It does not repair omitted assets from an import that was refused before producing a layer, fetch missing external resources, or guarantee Figma/native visual parity. No build, bundle, installer, archive, website or release metadata changes are included.
