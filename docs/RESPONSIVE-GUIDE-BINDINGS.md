# Responsive layout guide bindings

A Design layer can now stretch its layout box to a durable span of columns, rows, or both on its direct frame/component/instance parent. The Responsive guide bindings inspector provides the actual guide choice, first cell, span, bind and detach controls. This is a saved relationship: resizing the owner or editing a referenced guide recomputes the position and dimension through the editor and source MCP derivation.

## Status recommendations

- **UI-23-027 — Stretch with layout columns: implemented locally.** An X binding uses the selected column span's first and last edges, including intervening gutters. It follows stretch, start, center and end guide geometry, margins and offsets across future owner resizes and guide edits.
- **UI-23-028 — Stretch with layout rows: implemented locally.** The independent Y binding uses the same durable behavior for rows. Binding either axis is one document transaction with Undo/Redo and normal save/reopen.
- **UI-26-024 — Layout guide constraints: remains partial.** Durable direct-parent column/row spans now work in addition to existing snapping. Square-grid line bindings, arbitrary edge/pin offsets, named-line constraints, and binding through intervening groups or to other frames remain outside this implementation. No complete Figma behavior/reference verification is claimed.

Bounds are expressed in the direct owner's local axes, before the bound layer's own rotation/reflection/scale. A transformed owner therefore carries the responsive layout naturally; the solver does not reinterpret world-space bounding boxes. Hard minimum/maximum dimensions clamp the resulting size while retaining the first guide edge. When available stretch-guide space is exhausted, each cell collapses to zero size, matching the rendered guide geometry; multi-cell spans still include their gutters. A collapsed owner transform does not require matrix inversion: the local relationship remains defined while the artwork can render collapsed. A path retains its original path coordinate space when resized. Bound containers propagate ordinary descendant constraints and nested direct-parent bindings.

## Optional model and lifecycle

The additive optional field is `layoutGuideBindings`, with independent `x`/`y` entries shaped as `{ ownerId, guideId, start, span }`. Cell indices are one-based; each index/span is an integer and their last cell cannot exceed 1000. Existing layout guides already have durable IDs. Shared file/MCP validation checks object shapes, bounded reference strings and numeric values before a transaction can mutate saved data. Older supported `.oui` files require no migration or new mandatory fields.

Guide geometry and visibility are separate: hiding a guide does not deactivate its binding. A guide edit with the same ID remains linked. Deleting/retyping a guide, shrinking its count past the selected span, moving the child to a different owner, or moving it to the page root detaches that axis at its last derived geometry. Undo restores both the relationship and prior geometry. A replaced ID never silently binds another guide with the same name. Out-of-document guide geometry also detaches safely instead of creating invalid coordinates.

Linked guide styles retain guide IDs through edits and propagation. Detaching or deleting a style retains the owner's last local guide definitions, so bindings to those definitions remain valid. Replacing a style with different IDs detaches old bindings during derivation. The guide inspector now guards owner edits and numeric drafts against current context changes; an update affecting a locked/managed linked style owner refuses atomically with inline feedback.

Copies of an owner hierarchy remap binding owner IDs. Page copies also remap regenerated local guide IDs while preserving shared style identities. Variant copies and restored missing mains remap internal owners. Component materialization remaps inherited child bindings to the corresponding instance owners; resizing a linked instance resolves those inherited relationships. Instance roots can retain their own binding override to an outer parent, and resetting it detaches it rather than inheriting the main component's unrelated parent relationship. A copied child without its owner drops the binding. System clipboard payloads must contain their binding owners; forged destination-only references refuse before paste mutation.

## Editing guards and bounded work

The inspector requires one current Design selection, Motion closed, visible UI and no modal. Drafts expire immediately on document/page/selection/mode transitions, including an away-and-back native Motion cycle. Inherited locks and managed instance descendants refuse direct binding changes. Edit their main component or detach the instance instead. Slides/whiteboard workspaces and derived boolean results do not provide this binding workflow.

Auto-layout flow children must first become absolute; fixed text boxes must first use fixed text sizing. An aspect lock, hug sizing on the bound axis, flow positioning, or automatic text-box sizing introduced later **suspends** the saved binding with an inspector explanation. Returning to compatible settings resumes it. A saved binding reserves its axis while active or suspended, so ordinary constraints do not compete on that axis. The view-only constraint overlay omits those ordinary lines and names the binding instead. Explicit detach preserves the current geometry and returns that axis to the existing constraint rules. Direct manual changes on a bound axis are recomputed by its relationship; frame-relative controls explain that the binding must be detached first.

Translation preflights descendant coordinates before moving them. Derived positions and dimensions stay within the existing document range. Responsive derivation has a 200,000 layer-visit budget per shared reflow call; expensive deeply nested combinations refuse the entire edit with a clear error, preserving the original document and Undo history. This bounds added work rather than attempting unlimited nested responsive layouts.

## Interchange and validation

SVG/raster exports use the saved resolved artwork. Both CSS-copy paths explicitly warn that they describe saved geometry and do not generate responsive guide relationships. Dev inspection describes the owner by name and cell span, with active/suspended/unavailable state; it omits raw private owner/guide reference IDs. Editable Figma Bridge transfer validates the optional metadata before page mutation and reports that responsive bindings are omitted. It transfers saved geometry, not a native Figma guide-constraint relationship. Bridge checks use the API mock, not a real desktop round trip.

Core coverage includes both axes and guide alignments, owner/guide/style changes, detach and suspension, hard limits, bound-container descendant constraints, malformed input, locks/managed/workspace guards, Undo/save, clipboard closure, instance materialization/root override reset, page/variant copies, coordinate overflow, work-budget rollback and CSS/inspection redaction. Actual browser checks exercise bind/resize/rendered dimensions, guide/style edits, deletion/Undo, save/reopen, context invalidation, Motion/lock/managed/flow refusals, reparent detach, explicit detach and locked linked-style feedback. Direct-source MCP checks prove durable spans, resize, save, Undo, deletion and whole-batch malformed-input refusal.

No build, bundle, native app package, archive, version, website or central feature-register update is included. Source MCP checks deliberately defer standalone bundled-server acceptance under the user's build freeze. Reference verification remains pending.
