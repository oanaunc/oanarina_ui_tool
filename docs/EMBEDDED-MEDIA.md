# Embedded video and animated GIF source workflows

This unreleased source adds local video layers on Design and Whiteboard canvases. It does not establish complete Figma parity or a shipping/native codec acceptance result.

- File → Place video imports MP4 or WebM. Files are embedded in `.oui`, decoded locally and given a saved JPEG poster. The inspector plays a preview, seeks through native controls, captures the current loaded frame as a new poster, replaces the clip (resetting playback defaults while preserving layer geometry), and exports its exact original bytes. Poster changes and playback settings support Undo and saved reopening.
- Play, pause and restart buttons operate on the actual canvas video. The editor never autoplays a video. Leaving its selection, opening a dialog/Motion, switching editor mode or blurring the window pauses playback. The inspector preview also pauses on context changes; preview and canvas audio are not deliberately played together.
- Loop, mute, start time and prototype autoplay are saved options. Start time applies on first load and explicit restart. Native looping repeats the whole source from zero. Mute changes the actual media element; audible speaker output has not been independently checked on a Mac.
- Prototype presentations render actual video with native playback controls inside the layer’s existing SVG transforms, shape clip, ancestor clip, opacity and effects. Autoplay first requires a proven affine rectangular clip intersection plus an actual on-screen, focused-document IntersectionObserver result. Entirely clipped clips receive no live source; scrolling a video out of the prototype viewport pauses it. Nonrectangular clips and masks conservatively require manual Play, because their exact visible area is not proven. Autoplay then follows browser policy; if blocked, the controls remain available with a Play prompt. Frame navigation unmounts the old video; Restart flow starts again from the saved time. Transitions use poster frames and begin playback when the transition ends. Video controls consume their own pointer interactions rather than firing the video layer’s click reactions. Motion authoring uses posters, without video/timeline synchronization.
- Animated GIF placement uses the existing local image path. Real screenshot tests verify changing red/blue rendered pixels in both canvas and prototype, alongside import/save. There is no GIF frame editor or animation encoder. GIF originals remain intact; PNG/JPG are still exports, while SVG retains the GIF and relies on the viewer’s animation support.

Video accepts at most 20 MB of source, 4096 pixels per edge, eight million pixels, a finite positive duration up to one hour, and a start/poster time strictly before the end. The overall project retains its 50 MB limit. Posters are PNG/JPEG up to 2 MB; captured posters are JPEG, resized to at most 1280 pixels per edge. Video alpha and full-resolution transparent poster preservation are not promised. Unknown-length/live streams, other containers, remote URLs, trimming, transcoding, audio editing, video rendering/export and Slides placement are outside this workflow.

Imported source URLs must be bounded, valid base64 with the expected MP4/WebM container signature. The browser then checks real decoded geometry/duration against bounds and saved metadata before playing. Container or codec failure leaves an explicit poster/error state; it is not reported as successful video playback. Runtime video uses validated Blob URLs, revoked on abort/replacement/unmount, under `media-src blob:`. No filesystem paths, remote media permissions or native IPC capabilities were added.

The additive optional `DesignNode.media` belongs to image layers. `image` remains the matching poster fallback for older readers; static artwork consistently derives its image paint from that poster. Versions 1 and 2 continue to parse. Metadata is checked on imported documents and normal store transactions before mutation. Import/replacement captures document/page/selection/editor context and aborts when it changes. Poster capture pauses the preview and copies its loaded frame synchronously, preventing a later seek or target change from replacing the intended frame.

The shared renderer’s static SVG/PNG/JPG exports contain only the video poster, with an explicit SVG description of the omission; the video source, sound and playback are excluded. The Figma Bridge validates metadata before creating pages, transfers the poster and reports omission of video behaviors. The saved-file MCP SVG endpoint retains its existing refusal of pages containing raster images; use the editor to export video posters. No real Figma video round trip is claimed. SVG effects/masks involving media use saved posters as mask sources; dynamic video masks and cross-platform/native rendering equivalence are unverified.

The synthetic fixtures contain only locally generated red/blue frames and a sine tone. Browser tests decode H.264/AAC MP4 and VP8/Opus WebM in the test browser. This is not a guarantee for every MP4/WebM codec, Safari/WKWebView configuration or installed OS media decoder. The browser’s [video element](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video) and [play promise](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play) define the playback and autoplay behavior used here.

Validation: 12 focused core cases cover additive compatibility, transactional refusal, exact byte limits, original-byte delivery, clipboard transfer, static export, Bridge preflight/omission and affine visibility. Browser checks cover actual MP4/WebM decoding, canvas playback/end/loop/mute/start, replacement, poster pixels, save/reopen/Undo, GIF animation, prototype clips/transforms/restart/navigation, invalid input/context aborts, offscreen audio suppression and scroll visibility. An independent reviewer reproduced and verified both the offscreen audio correction and exact SVG corner ownership. No native release or real Figma round trip was produced.

## Trim end

**Video end time** adds a non-destructive end point beside the start time, saved as optional `endTime`. Presentation pauses there, or returns to the start time when Loop is on. The embedded bytes are not cut.
