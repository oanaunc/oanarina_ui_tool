# Separate vector regions

Unreleased source implements a bounded subset of UI-14-043. Use **Vector → Separate vector regions…**, or the same button while editing vector points, with one visible unlocked compound path selected in Design mode. The dialog shows isolated SVG images of the original and proposed result. Apply creates editable region layers in one undoable edit; Cancel, Escape, blur and stale editor context do not change the document.

The operation separates existing disjoint filled regions. It does not draw a knife cut (UI-14-042), partition crossing contours, or split arbitrary vector networks. UI-14-043 should remain **partial** until those broader meanings and reference behavior are resolved. Figma desktop and native Mac acceptance are not claimed by the DOM/core tests.

## Geometry and appearance

- Closed, nonintersecting cubic contours retain their anchors and handles; there is no curve flattening. Nonzero winding is canonicalized before classification. Internal contours that contribute no nonzero boundary are removed and their count is shown. Even-odd holes remain holes. Each outer filled boundary and its immediately enclosing holes become one path; a filled island inside a hole becomes another independent path.
- The original layer ID becomes a group, retaining its parent layout slot, size, position, rotation, reflection, render scales, opacity, blend/isolation, export settings, prototype reactions/references and accessibility metadata. Existing references continue to address the group. Main-component source edits propagate the group and region children to instances through the existing component synchronization; managed instance children cannot be edited directly.
- Children retain the original scaled coordinate box and parent-relative origin, with independent cubic contours and materialized solid fill stacks. Their layout bounds are deliberately **not tight** to each region. Group resizing subsequently follows normal group behavior rather than the former compound-path behavior; width/height animation tracks on the source are refused, and original width/height bindings are materialized. Group and child geometry can be edited separately using existing tools.
- Solid fill stacks retain order, paint opacity and node opacity. Group fills and strokes are empty. Paint/stroke/text styles affecting changed paint fields and fill/stroke/geometry variable bindings are detached; children receive no copied style or variable bindings. Unchanged group opacity bindings and variable-mode context remain.
- The original leaf's `clip` flag had no descendants to clip. The new group materializes `clip: false`, so an overhanging cubic is not newly clipped to a rectangle. Ancestor transforms, clipping and sibling mask context remain.

## Atomic refusals and limits

Visible strokes must first be hidden or converted using Outline vector stroke. Gradient/image fills (including hidden saved non-solid paints), visible effects, mask sources, media, live booleans/boolean ancestors, component definitions on the path, automatic layout on the path, open/degenerate/crossing/overlapping/touching contours and fewer than two filled regions are refused. Node animation tracks, including hidden tracks, are refused before opening. Slides/Whiteboard, Motion, hidden/locked ancestors and instance ownership are guarded. Component/layout derivation must preserve the complete planned group/child data or the entire transaction is rejected.

Input is bounded to 32 contours, 512 anchors, 200,000 path characters and finite local anchors/controls within ±1,000,000. The source coordinate box must have positive finite dimensions within the document limit. Page growth respects 20,000 layers. Preview context is limited to 2,000 layers. Document/page/selection/source identity, mode, modal, Motion/time, UI visibility, tool, vector-edit target and camera are captured; stale proposals cannot apply. No schema changes are required; existing `.oui` versions 1 and 2 preserve the result.

## Verification

Core tests cover nested holes/islands, nonzero winding, exact curved controls, affine world mapping, materialized styles/bindings, compositing metadata, bounded malformed/unsupported input, source component propagation, settled auto-layout footprint, one Undo/Redo entry and `.oui` parsing, plus lock/instance/stale context refusals. Browser tests exercise menu and point-tool entry, real original/result SVG pixels (holes, islands, translucent paint stacks, own and ancestor transforms and overhanging curves), preview/save immutability, actual Apply, independent point editing, Undo/Redo, repository reopen, source component synchronization and cancellation/refusals. Builds, native packaging and release artifacts remain frozen by user request.
