# Asset export delivery

Source implementation after dev.12. This work does not create an installer, release, version bump or website deployment.

The export dialog exposes saved profiles for any single ordinary design layer, including frames and slices. Each profile has SVG/PNG/JPG format, filename suffix, optional layout guides, Layer/Frame bounds or Artwork bounds, custom scale from 0.01× to 64×, and optional width or height sizing. One constrained axis is exact; the other is rounded up to whole pixels while preserving the aspect ratio. Layer bounds remove the target’s world transform; Artwork bounds keep canvas orientation and supported painted bounds. A slice always crops its own transformed rectangle from all overlapping visible page artwork.

Profiles remain optional `.oui` metadata, with up to 20 per layer. Existing 1×–4× profiles and project versions one/two remain readable. An unset list supplies one current default-format profile; an explicit empty list opts the layer out of batch export. New profiles consume the local default export-format preference. Existing saved profile formats are retained. Profile edits use shared Undo/Redo and validate at import, store and post-reconciliation boundaries. Locked hierarchies cannot author independent profiles; their existing/inherited profiles can still be exported read-only. Instance roots and managed instance children support independent exportSettings overrides: their profiles survive source changes, and resetting overrides restores the latest inherited main profile. A post-reconciliation check refuses any discarded profile edit atomically. The integrated inspector exposes profiles for every single selected layer.

JPEG quality is now a real control, from 10% to 100%, with 95% as the previous default. It is optional saved profile metadata and also available for combined exports. PNG and SVG ignore the quality value. The JPEG canvas is filled white; PNG retains transparency. SVG keeps the existing text/image/font rendering contract and does not add new text-outline or stroke-conversion options.

Batch export supports selected layers, selected frames, selected slices, or all explicitly configured layers on the current page. Each profile produces one asset. The app sanitizes filenames, bounds UTF-8 lengths and resolves case-folded collisions while preserving numeric collision suffixes. It creates one ZIP with `assets/` and `manifest.json`. Every manifest asset records its filename, format, actual pixel dimensions, effective scale, encoded byte count and SHA-256 digest. This is a downloadable directory in an archive; choosing or synchronizing an arbitrary native output folder remains unfinished.

Every SVG, embedded font/image reference, dimension and filename is captured before asynchronous rendering begins. Rendering works from immutable job copies. Programmatic snapshot exports can finish independently of later document changes. The dialog additionally cancels work after project, page, selection, modal, editor mode, UI visibility or motion-time changes, and exposes a Cancel export button. Cancellation during decoding, between assets or before packaging produces no partial archive. ZIP assembly itself is synchronous and checks cancellation before/after.

Visible embedded images are decoded before preview/export so a broken raster does not produce an apparently successful blank asset. Hidden or zero-opacity unused image paints do not block export. Resource errors, invalid/hidden target bounds and excessive output dimensions are reported explicitly. The raster cap remains 16,384 pixels per edge and 80 million pixels. Batches support at most 200 assets, 100 MB of source SVG and 100 MB of final output including ZIP overhead. SVG keeps large-vector bounds without allocating a raster surface. Font availability, glyph overflow, complex mask/clip bounds, color profiles and exact Figma export parity retain their existing limitations. PDF remains a separate unfinished design-export requirement.

Editable Figma Bridge import validates the additive profile metadata before creating pages and explicitly reports profiles as omitted. The saved `.oui` and delivered SVG/PNG/JPG assets retain their separate roles. No direct binary `.fig` export or desktop plugin acceptance is claimed.

Validation covers optional metadata/import rejection, history and both project versions, inherited locks/managed objects, profile defaults, fractional bound rounding, transformed layers and slices, filename collision/Unicode limits, immutable async snapshots, valid ZIP structure, independently computed SHA-256 digests, cancellation and broken image preflight. Production browser cases check actual PNG/JPEG pixels and dimensions (including a 0.1-pixel-wide frame at 64×), encoded JPEG preview fidelity, profile save/reopen, overlapping slice contents, ZIP files/checksums, preview, cancellation, mode-only context changes, JPEG compression changes and PNG independence. Existing frame, image editing and paint export regressions are included in the recorded validation. No new native build or system save-panel acceptance run is claimed.

Final isolated validation: 741 core tests in 72 files, 40 real MCP protocol tests plus TypeScript check, production compilation, 30 combined browser regressions followed by nine export cases after final preview/quality/fractional refinements. An independent reviewer reproduced and verified the fractional raster fix and checked the capped 200-asset work bound. These checks do not establish native save-panel or Figma desktop parity.

The subsequent integrated instance-root and managed-child cases exercise independent saved profiles, source changes, reset and Undo. See the [source integration report](UNRELEASED-IMPLEMENTATION.md) for the combined test results and the current build/download freeze.
