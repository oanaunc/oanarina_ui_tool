# SVG text as outlines — bounded export stage

`UI-40-024` is **partial**. Export → SVG options → Text geometry → **Glyph outlines · supported fonts** converts eligible displayed text into real glyph paths in the exported snapshot, quadratic for TrueType outlines and cubic for CFF. It never substitutes editable `<text>` on failure. Original text, fonts, bindings, component links and geometry stay editable in the project; exporting creates no document Undo entry. Changing a saved layer export profile uses normal Undo and `.oui` persistence. Combined-export choices are local to the dialog. Existing appearance/editable-text choices and absent settings retain their prior output bytes. No new native, network or font-filesystem capability is added.

## Exact face and positioning contract

New conversion requires a loaded, still-active browser `FontFace` with the exact registered bytes and descriptor. A later unmanaged same-family face in `document.fonts` refuses rather than guessing which face wins; preceding CSS-connected faces are safe only because the exact managed face is later in the font source and covers every used glyph. This follows Font Loading3 iteration order and CSS Fonts3 reverse composite-face matching. Mutated managed descriptors refuse, including exposed nondefault size-adjust/metric/feature settings. Missing optional newer FontFace getters mean their unsupported/default state and do not block older WebKit. the registration inspection itself is capped at 8,192 faces. Re-registering exact bytes repairs a deleted managed registration. The current document's authored family, when present, must select the same face as the registered family; conflicting descriptors, foreign matching weights/styles/subsets, missing coverage, restricted embedding metadata, synthesized weights/styles and split-subset selections refuse. The TTF's binary embedding flags are checked as well as asset metadata. No new proprietary font is bundled. Fonts from the existing permitted catalog/cache/project paths remain governed by their existing license policy.

The decoder accepts four outline forms, described in Font formats below. Composite TrueType glyphs resolve through their component offsets and scales, up to 64 components and 6 levels; point-matched components, scaled component offsets and cycles refuse. Each nonempty TrueType glyph must have hmtx left side bearing equal to glyf.xMin; other phantom-origin semantics refuse, including trailing-LSB-array glyphs. It parses bounded `head`/`maxp`/`hhea`/`hmtx`/`loca`/`cmap` tables and exact on/off-curve quadratic points; implicit on-curve midpoints are retained. No font bytecode is executed by the decoder. All eligible Unicode base cmaps must agree, including missing-glyph results. Unknown Unicode base mapping formats refuse; format 14 variation-selector metadata is ignored.

Exported text carries no language, so shaping checks read the default language systems of the `DFLT` and `latn` scripts, and their default-on features (`ccmp`, `locl`, `rlig`, `rvrn`, `calt`, `clig`, `liga`, `rclt`, plus `kern`, `dist`, `curs`, `mark`, `mkmk`, `abvm`, `blwm` for positioning). A conservative scan of those GSUB lookups refuses any input glyph that could be substituted. A ligature refuses only when its whole sequence is in the text, so the letters f and i are fine apart and refuse together. Other lookups need a feature setting this workflow already refuses. Covered GPOS lookups are accepted for pair positioning with first-glyph x-advance adjustments, including their device or variation records, and no second-glyph adjustments, with no lookup flags beyond skipping marks and ligatures. A base and combining mark compose into one character before lookup, and a mark with no composed form refuses, so mark attachment has nothing to do. Other potentially applicable positioning refuses. Legacy horizontal format-0 kerning is validated. This table scan is deliberately cautious, so a refusal from it is not final: see The browser check below. It does not claim full OpenType shaping. After proving glyph identity and advance-only positioning, native SVG character origins preserve the browser's actual kerning, tracking and physical alignment. The output needs no embedded font resource and eligible glyphs contain no `<text>` elements. Already-current imported glyph paths can be retained without fonts or a browser.

Paths are **unhinted vectors**. Font hinting and raster antialiasing can change edge pixels at small sizes. This is not a screenshot or an exact raster identity claim. The native positions and original font contours are preserved, rather than using nominal advances or a replacement font.

## Supported layout and explicit refusals

New conversion supports Latin and the other scripts where one character is one glyph, namely Greek, Cyrillic, Armenian, Georgian, kana, Han and Hangul, including line breaks and wrapped lines, all LTR, one exact face per character range, font sizes 1–4,096 px and nonnegative tracking. Scripts that join or reorder refuse. Left/center/right alignment, vertical placement, ordinary solid/none fill stacks and opacity and signed affine ancestry use the shared renderer. Export artwork bounds conservatively include glyph control hulls, including descenders/overhang outside a short authored box. Existing ancestor clips, explicit frame bounds and slice viewports still intentionally crop artwork. Bounds are conservative, not paint-tight.

Gradients and image paints refuse because native text glyph-cell paint space differs from outline ink bounds. Explicit font fallbacks, features other than `kern` 0/1, small caps, superscript/subscript, decorations, links, own clipping, justified/RTL text, paragraph overrides/lists, ellipsis/max-lines, hanging quotation/vertical trim, text backgrounds, text-on-path and stroked text refuse. Mask/Boolean/visible-effect hierarchies refuse against the original source before export ghosts can erase ancestor effects. Sampled Motion conversion and generated layout-guide labels refuse. Existing imported current outlines remain their established appearance path. Unsupported new conversion never falls back to plain text or omits a filter.

Limits: 20,000 source/export layers, 256 ancestor levels, 64 text layers, 512 displayed characters per new layer / 2,048 total, 100,000 decoded glyph points per export, 2 MB generated path per layer, 20 MB per font file, 64 MB per font after WOFF2 decompression, 100 MB decoded distinct font data per export, 256 variable instances per font. The decoder additionally bounds table directories, cmap/shaping coverage, class/pair work, glyph contours and glyph points, and the limits under Font formats. These apply to SVG export and Booleans; PDF embedding keeps its own static TrueType rules. Font decoders are cached within one export only. Refusals happen before download; temporary paths are never published to the document.

## Font formats

**TrueType `glyf`** is read as stored.

**CFF (`OTTO` OpenType).** Type 2 charstrings run as drawing only. All path operators, the four flex forms, stems and masks (skipped), local and global subroutines, widths, and `seac`-style composites through `endchar` are read. CID-keyed fonts select their font dictionary per glyph through FDSelect formats 0 and 3. The plain arithmetic operators run; `random` and the storage and conditional operators refuse. A font matrix that disagrees with `head.unitsPerEm`, synthetic fonts, Type 1 charstrings, predefined expert charsets under a composite, and malformed operand counts refuse. Bounds: 513 stack entries, 16 subroutine levels, 200,000 operators per glyph, 8,192 points and 512 contours per glyph.

**Variable TrueType.** A glyph instances through `gvar` at normalized coordinates, after `avar` version 1 segment maps. Shared, private and all-point tuples, intermediate regions, inferred deltas for untouched points, composite offset deltas and left phantom origin shifts are applied. Coordinates come from what the browser puts on the face: `font-weight` for `wght`, 100 for `wdth`, the style for `slnt` and `ital`, and the layer or range's chosen axis values over those. An axis the font lacks is ignored and values clamp to the axis range, as a browser does. Optical size follows the CSS font size unless a value is chosen, and does not follow zoom or transforms. A weight inside a variable face's declared range counts as exact. Bound: 50 million delta operations per font.

WebKit drops a chosen `opsz` equal to the font's default and draws the automatic optical size instead, while Chromium honors it, so that one value has no single drawing and refuses with a reason to choose another. WebKit also treats an `fvar` font with no `STAT` table as legacy GX and rescales `font-weight`, which clamps to the axis minimum. The browser check catches that and refuses; chosen axis values are unaffected.

**WOFF2.** `font-woff2.ts` already held a bounded Brotli decoder with the RFC dictionary, so WOFF2 needed no new dependency. `woff2Sfnt` reverses the `glyf`, `loca` and `hmtx` transforms into a plain sfnt, and the outlines above read that. Each stream read is bounds-checked, and the rebuilt font stops at 64 MB. The known-tag table had been missing `COLR`, `CPAL` and `SVG `, which shifted every later tag, so a real WOFF2 never exposed `fvar` or `gvar` and a color WOFF2 was not recognized as color. That is fixed, for font inspection too.

**Still refused:** color fonts (`COLR`, `SVG `, `CBDT`, `sbix`), `CFF2`, AAT shaping (`morx`, `mort`, `kerx`), `avar` version 2, font collections, restricted embedding flags, and fonts with no format 4 or 12 Unicode cmap. PDF embedding stays static uncompressed TrueType; other faces stay rasterized there, as before.

## The browser check

The table scan only says a substitution might run, and it reads Latin rules only. So the actual browser is asked what it drew: the run is drawn by a canvas and by the decoded outlines, then compared glyph by glyph. A glyph fails when more than 0.6% of its ink has none of the other drawing within one pixel. An exact comparison cannot work here, because macOS darkens canvas text, and it had been failing every Latin run in WebKit. Origins come from the canvas's own layout, because the check proves which glyph appears and native layout already supplies placement. On 48 px rasters, correct text measures 0.000 to 0.003 and real substitutions 0.05 or more in both engines; a near-identical ligature measures 0.014 and still fails.

The check always runs for CFF, variable and WOFF2 faces, for text outside Latin, and whenever the table scan refuses. Plain static TrueType Latin text that the scan clears skips it, as before. Failing refuses with the scan's reason, or a statement that the outlines differ from what the browser draws. Headless conversion has no browser and refuses as before.

A canvas can draw weight, style and automatic optical size, and no other axis. With other axes chosen, the check runs without them and proves glyph identity, because those axes change shapes rather than which glyph appears. A font that swaps features by axis (a `FeatureVariations` table) cannot be proved that way, so such a font refuses in that case when the table scan is also unsure.

## Context, compatibility and interchange

`svg.textMode: 'outline'` is an optional saved-export enum supported in both `.oui` v1/v2; malformed values reject before mutation. No required document-node schema changes occur. The source MCP can author/validate this saved profile and Undo it, but headless new glyph conversion explicitly refuses because native layout is required. Headless reuse of existing imported outlines still works. Bridge validates the option and explicitly reports that saved export profiles are omitted; API mocks are not a real Figma desktop round trip. SVG glyph paths can be reimported as ordinary filled vector geometry.

Export options retain source-context and local candidate receipts. Pending export delivery cancels on document/page/selection/mode/modal/Motion changes and font-revision changes; a fresh current retry succeeds. Native measurement probes rebuild if detached. No document state is changed by font parsing, measuring or export failure.

## Validation

Scoped tests use the existing open-license Lato TTF, malformed/ambiguous real-font table mutations, exact quadratic midpoint cases, headless/imported-path bounds, font proof failures, Bridge omission/atomic refusal and direct source MCP apply/Undo. Actual browser checks cover AV/WA native kerning, glyph-only output, unhinted silhouette comparison, signed affine right-aligned translucent text, SVG reimport, short-box descender bounds/frame crop, saved profile Undo/save/reopen, refusal routes, font-revision cancellation, retained context callbacks and deleted native font registrations. In the 96 px Lato AV/WA fixture, the mean RGBA difference is approximately 1.78/255; every substantially painted pixel is within one pixel of the other raster's silhouette. This evidence is bounded to the tested faces and supported workflow.

Primary references:

- [Figma static export settings](https://help.figma.com/hc/en-us/articles/13402894554519-Export-formats-and-settings-for-static-designs) describe text outlining as an SVG export setting; Forma's bounded opt-in implementation does not claim the full reference behavior or default.
- [OpenType glyf](https://learn.microsoft.com/en-us/typography/opentype/spec/glyf), [cmap](https://learn.microsoft.com/en-us/typography/opentype/spec/cmap), [GSUB](https://learn.microsoft.com/en-us/typography/opentype/spec/gsub) and [GPOS](https://learn.microsoft.com/en-us/typography/opentype/spec/gpos) define the formats and shaping boundaries.
- [SVG text character-position API](https://www.w3.org/TR/SVG2/text.html#InterfaceSVGTextContentElement) supplies native character origins after the supported glyph/positioning proof.

- [OpenType hmtx](https://learn.microsoft.com/en-us/typography/opentype/spec/hmtx) defines side-bearing/phantom-origin semantics.
- [CSS Font Loading3 font-source order](https://www.w3.org/TR/css-font-loading/#fontfacesource-css) and [CSS Fonts3 composite matching](https://www.w3.org/TR/css-fonts-3/#composite-fonts) support the bounded later-exact-face proof.

Final scoped evidence: 22 own browser cases, 46 corrected own/adjacent SVG and font/context cases, 55 affected headless checks, one direct source MCP apply/atomic refusal/Undo case, editor and source MCP TypeScript. The preceding full source core run passed 2,237 cases in 193 files before the final narrow proof/guard refinements; those refinements were checked with affected tests rather than relabeling that earlier full run. Private browser port 5384 is stopped after managed runs. No app/package/archive/native build was created.

Cache follow-up: saved-preview memoization, combined preview state and prepared ZIP state now invalidate on font revision. Prepared batches additionally carry a permanent synchronous source/revision receipt so an old retained Download handler cannot reuse earlier glyph geometry before React effects run. Fresh preparation reruns exact-face proof. Glyphs are decoded/charged sequentially: the cumulative 100,000-point refusal stops before decoding a later glyph (at most one individually bounded glyph overshoots the threshold).

Follow-up validation: 35 actual browser cases passed (24 text-outline cases plus 11 existing export-delivery cases), 20 affected parser/proof/domain cases passed, and editor TypeScript passed. The ZIP regression installs deliberately different late font bytes, changes font revision, invokes the retained Download callback in the same event and proves no download; fresh preparation refuses until the exact face is restored, then delivers glyph paths. Saved and combined preview invalidation are both exercised. The source MCP/profile and broader font/export evidence above remains applicable because this follow-up changes no model or MCP fields.

Formats evidence: decoding every glyph of 239 real local fonts refused only for side-bearing origins in a handful of glyphs and for unsupported formats, with no charstring, variation or stream failures. Those fonts were used locally and are not in the repository. Rendered against the browser at 120 px, cell by cell in Chromium and WebKit, STIX and Kohinoor CFF, Hiragino and Apple SD Gothic CID-keyed CFF, STIX Two, New York, SF and Kefa `gvar` with `avar` across weight, optical size, grade and width, and Inter, Commit Mono and KaTeX WOFF2 differ only by edge antialiasing, a mean 0.3% to 2% of ink. The same fonts pass the full export path at 12 to 200 px in both engines; a font with restricted embedding flags refuses. In the repository, `tests/support/cff-font.ts`, `tests/support/variable-curves-font.ts` and the transformed encoder in `tests/support/woff2.ts` build original fixtures from code, and `tests/e2e/text-outline-formats.spec.ts` compares them in both engines. Seeded bit flips across CFF, CID, `gvar` and WOFF2 glyph streams refuse or decode finite points and never hang.

WebKit notes: rasterizing an exported SVG in an `<img>` does not apply some kerning that live layout applies, so an image raster and native positions can differ there; it is the same with plain TTF and predates this work, and the formats spec compares live layout instead. A base and combining mark in decomposed text can also draw differently from the composed glyph, because CoreText can place the mark itself. So decomposed text outlines only where the browser check agrees, which depends on the font: Roboto's e with an acute passes, Lato's refuses. Chromium refuses such runs earlier, because `document.fonts.check` reports them as not ready.

## Bundled font coverage

A scan of the 262 bundled TTF files decoded every printable ASCII glyph in all of them, and 194 passed shaping for the sample "Sample text 123". The other 68 refused, 50 for a possible substitution and 18 for positioning this stage does not model; whether a font refuses depends on the text. A locale-specific `locl` form is not applied, so text that a browser would shape under a document language other than the default can differ.
