# Reusable interactive variant transitions

UI-28-029 has a real reusable authoring and presentation workflow. Implementation remains **partial**, and reference verification remains pending. Component slots UI-28-031/032/033 remain planned; this work adds no slot metadata or arbitrary instance-content ownership.

Select a main variant or content inside it, open **Prototype**, add or edit a **Change to variant** action, and enable **Change this receiving instance**. Choose another state from the same component set, configure the existing trigger/transition controls, and insert instances into a presentation frame. Each instance inherits the interaction and changes its own state. Existing actions with an explicit destination instance retain their separate target semantics.

The state chooser searches every supported variant and paginates at 200 options, keeping the currently selected state available outside the current search/page. It does not create thousands of option elements. Source and local candidate receipts prevent retained callbacks from applying after document/page/selection/mode/modal/Motion, reaction/action removal, or local search/page changes. Fresh rendered controls recover. Source hierarchy locks disable authoring. Native Space toggles the checkbox without starting a canvas gesture.

The optional `PrototypeAction.targetScope: 'self'` is valid only for `change-variant`, without `targetId`. `.oui` versions 1/2 remain compatible; absence keeps explicit target actions unchanged. Imported metadata, store changes, source MCP edits and Bridge input validate the new field before publication. Removing or changing authored interactions has normal Undo/Redo and save/reopen behavior.

At presentation time, the actual generated ancestry determines the nearest receiving instance. Each reaction is resolved separately before batching, including keyboard, gamepad and delay actions. Runtime action identities are namespaced per receiving owner/reaction to avoid collisions when several instances inherit the same action. Missing receivers, ambiguous memberships and destinations outside the receiving set refuse explicitly. The optional preview synchronization parameters are supplied only by presentation derivation; saved/default editor/MCP synchronization retains its original path.

Preview derivation uses stable generated identities based on the receiving instance and source layer. Authored identities remain reserved; deterministic suffixes avoid collisions. Existing real IDs are reused where the normal correspondence allows. Nested instance replacement materializes its actual subtree and retains the outer ownership, source correspondence, keys and Boolean visibility. An exposed outer instance-swap value may change in the unpublished presentation clone to represent that nested preview state. The saved source, component definitions, consumer overrides, local-library baselines and Undo history do not change. Hover and press restore prior presentation state, including nested receiving instances; Restart clears transient states.

The shared transition renderer continues to handle instant/dissolve/Smart Animate and the existing transition choices. The existing presentation reduced-motion policy suppresses visual interpolation while preserving the authored transition. Existing advanced Motion/progressive-effect transition refusals remain in place. No shader, media codec, native host or release artifact changes are part of this work.

Clipboard and page cloning retain scoped actions while remapping their actual component destinations through the existing reaction-reference graph. Published local libraries contain closed variant dependencies; installed consumers retain their saved artwork overrides while presentation changes stay transient. Editable Figma Bridge explicitly reports self-targeted interactive semantics as omitted, instead of treating them as an explicit destination. Mock API checks do not establish a native Figma round trip. SVG/raster exports continue to depict authored or explicitly sampled artwork; they do not produce an interactive application.

Bounds are explicit: at most 100,000 indexed document layers, 20,000 page layers, 10,000 variant memberships, 256 receiving ancestors, 1,000 actions per bounded action tree and 128 transient changed instances. A layer-state preflight allows at most two million products before derivation. Preview synchronization limits each source subtree to 20,000 layers, cumulative materialization to 100,000 layer copies/live layers, and the conservative source-plus-copied-node JSON payload to 100 MB per synchronization pass before copying another subtree. The byte budget can refuse a large valid source conservatively. Excess work raises an error; it does not partially install a preview state or publish document changes.

Limits: `self` means the nearest receiving instance, not an arbitrary ancestor component. Parent-targeted component transitions, Figma's complete inherited-versus-instance trigger precedence, automatic trigger merging and native reference equivalence are not implemented by this change. Scroll events are emitted by frame scroll hosts; nested receiving-instance scroll triggers are unavailable. Use the existing explicit-target frame reaction where appropriate. This does not add slots, native plugin self-target transfer, direct binary `.fig` export or cloud collaboration.

Primary reference: [Figma interactive components](https://help.figma.com/hc/en-us/articles/360061175334-Create-interactive-components-with-variants) documents inherited transitions between variants in the same set, including behavior and trigger precedence beyond this supported subset. [Figma slots](https://help.figma.com/hc/en-us/articles/38231200344599-Create-and-use-slots-to-build-flexible-components-in-Figma-Design) require editable arbitrary content with a separate lifecycle; that architecture remains future work rather than placeholder controls.

Validation includes real authoring, Undo/save/reopen, two independent root and nested receiving instances, exposed swap/Boolean preservation, hover/press restoration, newly introduced child interactions, keyboard/gamepad/delay ownership, shared Smart Animate/reduced-motion behavior, native Space, 125% short-window controls, large paginated choices and retained source/candidate handlers. Core coverage includes saved-state immutability, source-order-stable/collision-safe generated IDs, copy/library closure, existing explicit action atomicity/cycle refusal and embedded-content expansion refusal. The source checkpoint passed 2,087 core tests across 179 files, 42 actual browser cases (14 new and 28 existing prototype/Motion cases), editor and MCP TypeScript checks, and 80 direct-source MCP tests with no skips. No application build, native package, archive or website change is produced.
