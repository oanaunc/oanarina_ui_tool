# Mixed selected fill stacks

The Design inspector shows **Fills · Mixed selection** for two or more selected layers whose fill appearances differ. It reports each top-to-bottom stack position, paint kinds, how many selected layers have that position, and mixed visibility/opacity. Matching appearances are labeled **Same appearance** even when local paint IDs or inactive solid-paint parameters differ. The existing Selection colors tool remains separate: it scans selected descendants and replaces matching RGB values; the new fill-stack controls edit only explicitly selected layers.

Each position can be shown/hidden, assigned an opacity, removed or explicitly converted to a chosen solid RGB color. These operations affect that position only on layers where it exists. Other positions, paint IDs, gradient geometry/stops, image bytes, texture/pattern source and adjustments are preserved. Moving a position requires both positions on every selected layer. Add inserts a fresh independent solid fill at the top of every selected stack. Clear removes all selected fills. **Replace complete fill stacks** requires choosing a selected source layer and clicking **Apply source fills to selected layers**; this is the only implicit-looking whole-stack operation, and it is explicitly labeled. It clones supported fill data with independent IDs on changed targets.

Writes are atomic and add one Undo entry. Effective no-ops preserve authored IDs, absent legacy paint arrays, paint-style and variable links, and history. Actual fill-stack changes detach the competing paint style. Primary fill-variable links survive opacity and secondary-slot changes when the bound first paint identity/type/color remains unchanged; changing/replacing that primary fill detaches its fill binding. Other variable/style maps remain. Saved `.oui` version-one/two data needs no new fields or migration. Existing shared Artwork rendering provides ordinary SVG/raster/mask behavior; no export-only substitute is introduced.

All selected ownership must be editable. Inherited locks and managed instance descendants refuse the entire edit, rather than silently skipping layers. Instance roots support normal resettable overrides. Main-component edits propagate through existing derivation; the final selected paint data is checked after derivation so a workspace/component controller cannot silently replace the requested result. Motion, Home, hidden editor UI, non-Design inspector modes, modal dialogs and Slides do not admit these writes. Permanently invalidated source receipts prevent retained numeric/button callbacks from reviving after document/page/selection/mode changes, including away-and-back transitions in one event.

The bounded workflow supports 2–512 selected layers on a page of up to 20,000 layers, hierarchy depth 256, at most 100 fills per layer/4,096 selected fills and 16 MB of UTF-8 selected fill data. Changed documents must fit the 50 MB saved-file limit. Capacity, complete input and all selected ownership are checked before mutation. Video-poster surfaces and export slices refuse mixed fill writes; ordinary mixed node kinds, container/child selections and authored image fills are supported. A legacy `fill: none` fallback appears as its existing hidden paint until explicitly edited; authored empty stacks remain empty.

Every position whose paints are one kind has **Edit settings on N layers**, the full paint editor for that kind: gradient stops, angle and center, image fit and adjustments, pattern, noise, texture and shader settings. It shows the first layer that has the position. A change sets only the setting it touches on every layer with that position, so a shared angle leaves each layer's stops alone. A position that mixes kinds asks to be converted first. Canvas gradient handles remain a single-layer tool, because each layer has its own box.

When selected strokes differ, the stroke section becomes the same position list. Each position can be shown, hidden, removed, reordered, given an opacity, width and position, converted to solid, or edited through shared paint settings; a stroke stack can be added to, cleared, or replaced from a selected layer. Selected strokes that already match keep the ordinary stroke editor, whose edits apply to all of them. Dashes, caps and joins remain ordinary stroke editor settings, reachable by selecting one layer or matching the stacks first.

Category-wide Figma and native reference acceptance is not claimed.

Validation: pure/store checks cover summaries, absent positions, independent IDs, per-slot preservation, input/count/depth bounds, inherited ownership, source propagation and instance reset, no-op styles/variable bindings, exact Undo/parse persistence and post-derive refusal. Actual Chromium checks exercise reachable controls, shared SVG RGBA pixels for solid/gradient/image fills, saved reopening, retained blur/button callbacks after same-event context cycles, single-layer inspector preservation, and a short 125% interface viewport. Related existing paint/color/range workflows remain part of focused acceptance.
