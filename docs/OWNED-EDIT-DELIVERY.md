# Owned post-edit UI delivery

Shape Builder Apply, outlined-text Boolean Apply and component documentation generation now share a narrow post-transaction delivery fence. Their normal validated editor transactions still author the artwork and one Undo entry. The fence governs only the following selection, page, vector-selection, camera and tab update; it never rolls back already-committed artwork, writes document/history fields or replaces the store transaction pipeline.

The helper captures the current editor context, font revision, selection, camera, tool, vector state and tab, then observes every synchronous store notification through the edit. The caller's final validation must succeed before its candidate document identity becomes the owned publication. A foreign document, mode/page/selection/camera/font/tool/vector/tab departure permanently invalidates delivery, even if another subscriber restores the original values or owned candidate before `edit` returns. Both notification state and current store state must match. A genuine no-op may still deliver selection only when the store emitted no notification and the complete original context remains current. The temporary subscription is removed on every exit, including mutation, validation or delivery exceptions.

Delivery is a single typed partial-state publication limited to ephemeral fields. Its builder must be pure; the context is checked again immediately before publishing. The ordinary store remains responsible for page/camera behavior. Shape Builder additionally resets only its original local context, so a synchronously opened replacement session is not unconditionally cleared.

Nine actual browser regressions first failed against the original paths: each workflow committed its authored result and then incorrectly overwrote a subscriber's replacement-document or away/back context selection/navigation. The same tests now require the authored result and history to survive while late UI delivery is suppressed. The mode-cycle cases Undo, re-review and Apply again to prove fresh positive recovery. Focused headless tests cover ordinary edits, exact no-op delivery, permanent context cycles, replacement, and subscription cleanup on throws; existing domain browser tests retain their regular Undo, save/reopen, geometry and export checks.

This is a scoped reliability change for these three workflows. It does not claim that every historical `edit` → UI callback elsewhere has been audited. The local plugin sandbox has a separate author-owned delivery fence.
