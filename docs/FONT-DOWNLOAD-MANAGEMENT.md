# Font downloads and device cache

The Font Library includes **Downloads and device cache**. Preview, Apply, document loading and retry use the same FIFO family queue: three active families, up to 64 waiting families, and one shared operation for concurrent requests for the same family. Queue rows show queued, active, ready, failed or canceled status. Failed or canceled families can be retried. The last 40 settled queue rows are retained for this session. These controls do not edit the document or create Undo entries.

Cancellation stops queued requests, network reads and staged FontFace decoding before publication. Decoded faces are held until every face in that family is ready. The publication step seals cancellation before synchronously adding faces to the browser's font set. Cancel is disabled during publication/cache completion. Already registered fonts remain available after cancellation. Download/retry never applies a font to a different selection: the existing font-application context proof still captures the source before awaiting the queue, including away-and-back changes.

**Reload installed catalog snapshot** reads this installation's `font-catalog.json` again with cache revalidation. It does not query or update Google's live font catalog. All concurrent catalog readers share one request, including concurrent reloads. Payload validation precedes replacement; a failed reload retains the prior valid in-memory catalog and can be retried. This is the October 29, 2026 snapshot and the existing 24 bundled open-license families, with no new font bundles or licenses.

Catalog responses are capped at 4 MB / 5,000 unique families, with bounded validated literal names, weights, axes and labels. Manifest/CSS responses are capped at 1 MB. Each downloaded file is capped at 20 MB; a family is capped at 256 faces and 64 MB of decoded font files. Family files are fetched sequentially within each worker, so the three-family queue also bounds concurrent font-file fetches. Google CSS only supplies HTTPS `fonts.gstatic.com` file URLs. Face descriptors, font signatures and embedded assets are checked before registration. This does not establish Unicode glyph coverage or allow arbitrary font-service URLs.

**Inspect device font cache** reports per-family file count and decoded font bytes, including the removable downloaded portion and protected portion. **Remove downloaded files** only removes recognized `google`/`bundled` cache entries that permit embedding. Imported (`user`), restricted, absent/unknown provenance and malformed/legacy cache records are preserved. Read/modify/write is an IndexedDB transaction, preserving imported faces when family names/descriptors collide. A family with a queued/active load cannot be cleaned until that operation settles. Unrecognized records are counted without being removed. Inspection is bounded at 5,000 records, 20,000 files and 256 MB of recognized decoded font data; each valid family cache record has at most 512 faces / 100 MB.

Cleanup only changes this browser/device's IndexedDB font cache. It does not remove loaded FontFace objects, current-project embedded assets, licensed fonts installed on the computer, imported files, or saved projects. Removed downloaded fonts can be fetched again in a later session when needed; loaded families remain usable in the current session. Cache inspection is explicit and does not imply the in-memory session fonts have all been persisted. Storage failure can leave a successful download usable for this session without persisting it. Byte counts exclude browser database overhead. No file-system or native IPC permissions were added.

## Validation

Pure tests exercise the shipped catalog, malformed payloads, request deduplication, refresh recovery, queue concurrency/FIFO/cancellation/retry/publication sealing, streamed body limits and selective cache accounting. Runtime tests verify cancellation during delayed FontFace decoding publishes no faces, malformed refresh preserves the previous catalog, and aggregate family limits refuse before registration. Real Chromium checks use delayed bundled-font responses, actual FontFace decoding, IndexedDB cleanup, preserved imports/loaded faces/project font embedding, snapshot reload and retained-control context invalidation, alongside the existing font/application tests.

## Remaining limits

Catalog refresh is an installed-snapshot reload, not a live Google update. Queue limits are per app/browser JavaScript session; separate tabs can each download. Browser storage quotas, browser eviction and cross-device caches are not managed. This is font-cache management only, not the full image/media/asset-cache feature. Native Mac reference checks and Figma font availability remain separate; this source pass does not build an app or claim native font-service parity. All commercial fonts still require the user's own installation/license; none are redistributed here.
