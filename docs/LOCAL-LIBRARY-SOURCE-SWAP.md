# Reviewed local library source swaps

In **Assets → Libraries → Swap local library source**, choose an installed dependency and a saved replacement component-library snapshot, from a file or the local cache. Explicitly map every old stable asset key to a distinct incoming key of the same kind, then review the complete mapping before applying. Cancel, disclosure/context changes and newer local choices invalidate prepared work. File reads are bounded to 20 MB, and late callbacks cannot publish a snapshot into a replacement editing context; synchronous parsing itself is not interruptible.

The supported subset is a whole-library bijection containing only component and complete variant-set asset groups. Style, token, guide or other reference-map ownership is refused. An already-installed replacement library is refused rather than merged. Missing cached definitions, dirty accepted baselines and locked source hierarchies must be resolved first. Original immutable snapshot files/cache entries are never rewritten.

Every corresponding local definition layer keeps its ID. Existing instance IDs, generated child IDs, prototype references and component links remain stable. New source IDs map to those same local identities. Component-set identities and variant links are retained. Source root names may differ, while descendant trees must have identical relative layer types and names, unique among siblings. The matcher does not guess duplicate sibling roles or silently flatten incompatible trees. Root mappings are always explicit, including otherwise similar names.

Exposed component properties must match uniquely by type, name and corresponding layer target. Their existing local property IDs and consumer values are retained. Slots must target every corresponding frame; their source slot IDs may change, in which case instance override flags and managed frame markers are remapped together. A reused slot identity referring to a different area refuses. Customized local slot children remain independent and keep their IDs. Unsupported topology, dropped properties/slot areas, extra claimed live layers or inconsistent metadata refuse before any published document mutation.

Apply uses the ordinary validated library-install pipeline and the exact original document receipt, in one Undo step. Undo and redo restore complete source ownership, metadata and artwork. The new dependency has the replacement library/source identity, accepted version, advisory deprecation status and reference maps; its future updates use those maps. The old source snapshot remains available independently in the cache or on disk. Replacement source artwork and its source history become authoritative; consumer overrides remain literal overrides. The existing cached definitions page is retained, including its user-visible page name. Existing consumer locks and overrides retain normal component inheritance semantics; cached definition locks block source replacement.

Matching is bounded to 20,000 definition layers, 128 hierarchy levels and 512 asset groups. Document inspection is capped at 100,000 layers and accepted baseline inspection at 12 MB of UTF-8 text; existing 20 MB snapshot, project, font-conflict and component-slot limits also apply. The UI pages mappings in groups of 24 and displays exact old/new keys plus matched layer/property/slot counts. It does not claim glyph/font equivalence, a Figma desktop round trip, cloud-library replacement or an arbitrary structural migration.

No new persisted schema fields or .oui version changes are required. UI-29-025 remains **partial**: this is a conservative local component/set replacement workflow, without cross-library style/token migration, partial dependency merges, ambiguous per-layer manual mapping or cloud source swapping.
