# Opt-in component property relevance

UI-28-024 has a reachable local authoring and instance workflow. It remains partial and reference verification remains pending. Forma's behavior is explicitly opt-in; existing files keep all exposed controls visible.

In Resources → Components and variants, choose a main component and enable **Hide irrelevant properties**. Its instances hide text and instance-swap controls when the corresponding generated layer or an ancestor inside the instance has authored visibility turned off. A Boolean that controls its own layer stays available, so the layer can be restored. A Boolean nested below a different hidden ancestor is hidden until that outer layer is restored. Opacity, clipping, masks, off-canvas location, empty paint and zero size do not determine relevance.

The instance inspector offers **Show irrelevant properties**, an unsaved view control that reveals the filtered controls with an explanation. Hiding controls never removes values, resets overrides, detaches nested instances or changes artwork. Revealed values can be edited while their layers remain hidden. Showing a layer again restores its controls and retained values. Existing property groups and preferred swap choices are preserved.

Nested exposed swaps now preserve the outer target identity and matching key when materializing the replacement component. Outer Boolean visibility is reapplied after swaps, so swapping and showing/hiding the same nested target no longer depend on property declaration order. Repeated synchronization retains the target ID; ordinary standalone instance swaps retain their own source identity.

The optional `componentMetadata.hideIrrelevantProperties` Boolean is validated on main components before import or store publication. Absence preserves prior `.oui` version 1/2 behavior; disabling in the authoring UI removes only this optional field. Main changes have normal Undo/Redo and save/reopen behavior. Clipboard definitions and local library snapshots retain the setting with their ordinary graph remapping. The source MCP uses the same validation, persisted changes and atomic batch refusal. No new privileged MCP operation is introduced.

Author editing uses the existing inherited-lock and complete variant-set guard. Exposed value changes retain target/source lock and component-cycle guards. New controls also bind to their exact document/page/selection/mode/modal/Motion context, with permanent invalidation across changes and recovery through a fresh rendered control. The manager's local source chooser has an independent synchronous generation proof. Authoring requires the Components dialog; instance editing and temporary reveal require no modal. Reveal/hide has its own synchronous reactive generation, so removed or previously revealed controls cannot mutate through retained handlers, including an away/back cycle. Sampled Motion does not allow these edits. The temporary reveal control does not write the document or Undo history.

Inspection indexes at most 100,000 layers and walks at most 256 ancestors per uncached chain, with cached visibility results. Unavailable, ambiguous, excessively deep or over-budget target visibility keeps the corresponding control visible and explains the uncertainty. It does not treat uncertain data as irrelevant. At most the existing validated 1,000 exposed properties are inspected. This does not implement cross-instance multi-selection editing, nested-property exposure authoring, variant-dependent conditional expressions, permissions, cloud behavior or a native Figma property panel.

Editable Figma Bridge validates the optional Boolean before creating a page and reports the relevance setting as omitted. Ordinary artwork and supported exposed properties still transfer. SVG/raster outputs are unchanged because the setting controls the editor's inspector, not rendering. Bridge tests use the API mock; they are not a native Figma plugin round trip. Frozen downloadable plugin/MCP archives are not regenerated.

The current [official Figma component property documentation](https://help.figma.com/hc/en-us/articles/5579474826519-Explore-component-properties) states that simplified instances are deprecated starting March 23, 2026 and all component properties and layers are shown by default. It separately describes hidden exposed nested-instance properties. Forma's optional relevance rule is an independent, documented workflow; this change does not claim exact current or historical Figma semantics.

Validation covers opt-in/default compatibility, ancestor Boolean restoration, retained hidden overrides, unavailable/deep targets, bounded indexing, preferred swaps, clipboard/library graph persistence, malformed import/store/MCP/Bridge atomic refusal, inherited locks, real inspector/manager interactions, Undo/save/reopen, retained same-event handlers and short-window 125% keyboard access. Validation passed 2,029 core tests across 174 files (`npm test -- --maxWorkers=2`), editor TypeScript, MCP TypeScript, 78 source MCP checks, and 23 actual browser checks (14 new and nine existing component workflows). Twelve new core cases include both nested-swap/Boolean declaration orders and local library updates. The browser checks use a fresh private Vite server; an earlier stale HMR/dynamic-import store run was discarded, and wrapped-text/duplicate SVG-definition assertions were corrected before the final green run. Independent source review found no remaining blocker. No application build or release artifact is produced.
